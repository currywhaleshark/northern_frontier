# 조정 하사품 개편과 고유기물 — 설계

- 작성일: 2026-07-28
- 발단: 세공을 꼬박꼬박 바쳐도 격년 하사품이 "도구 2개" 수준이라 보람이 없다
- 범위: 하사 물자의 티어·수량 개편 + **하사로만 얻는 고유기물** 계열 신설
- 선행작업: `DESIGN-2026-07-28-annual-climate-weather.md`의 W1~W4
- 구현계획: `IMPLEMENTATION-2026-07-28-court-grants.md`

## 1. 문제 진단

**요구는 복리로 늘고, 보상은 상수다.**

| | 스케일 | 5년차·인구 20 |
|---|---|---|
| 요구 | `(1 + 0.3×(연차−1)) × (0.7 + 인구/40) × 등급배율` = **2.64배** | 가죽 21 / 곡물 66 / 가죽옷 16 급 |
| 보상 | **스케일 없음** | 도구 2 **또는** 무명옷 3 (격년, 50/50) |

현재 하사 로직은 이게 전부다 (`courtTribute.ts` `grantFullTributeReward`):

```js
if (tribute.year % 2 !== 0) return;
if (rng() < 0.5) tools += 2; else cottonClothes += 3;
```

교역가 환산으로 2년치 납부 **300+** 대 하사품 **8** — 약 2~3%. 연차가 갈수록 격차가 벌어진다.

## 2. 원칙 — 실용품은 보장하고, 선행 물자와 기물은 덧붙인다

하사품은 세 층으로 나눈다. 고유기물이 실용 물자 자리를 대신하지 않는 것이 핵심이다.

| 층 | 무엇을 | 지급 방식 | 도움의 성격 |
|---|---|---|---|
| **실용 물자** | 현재 단계에서 바로 쓸 수 있는 것 | **항상 1품목**, 추가 1품목 확률 지급 | 양으로 숨통을 틔운다 |
| **선행 물자** | 아직 생산하기 어렵거나 교역 의존적인 것 | 별도 확률로 0~1품목 | 소량이어도 존재 자체가 도움 |
| **고유기물** | 하사로만 얻는 특별한 물건 | 물자 지급 후 **독립 보너스 추첨** | 장기적인 행운과 개성 |

실용 물자를 찔끔 주면 지금처럼 "도구 2개"가 되고, 선행 물자를 잔뜩 주면 등급 진행이 무의미해진다.
양으로 돕는 것과 존재로 돕는 것을 분리하고, 고유기물은 어느 쪽도 빼앗지 않게 한다.

하사품은 세공의 환급금이 아니므로 세공 요구량과 똑같이 30%씩 커지지는 않는다.
연차 보정은 완만하게 증가하고 상한을 둔다.

```ts
grantYearScale(year) = Math.min(1.8, 1 + 0.08 * (year - 1));
finalAmount = Math.max(1, Math.round(baseAmount * grantYearScale(year)));
```

10년차에 약 1.72배, 11년차부터 최대 1.8배다. 등급 상승은 수량을 또 배증하기보다
후보 물자의 질을 높이는 방식으로 반영한다.

### 물자 풀

| 분류 | 품목 |
|---|---|
| 연료 | 장작 · 숯 |
| 식량 | 곡식 · 보존식(보존육·자반·건어물) · 장 · 김치 |
| 의생활 | 가죽옷 · 무명옷 · **가죽신** |
| 자재 | 철 · 도구 · 소금 |
| 군수 | 창 · 각궁 · 조총 · 화약 |
| 자산 | 은 · 사치품 |
| 축산 | 가축 |

**짚신은 제외한다.** 가내수공업으로 자급되므로 하사받을 이유가 없다.

### 등급별 배치와 기준량

아래 수량은 1년차 기준이며 실제 지급량에는 위 연차 보정을 적용한다.
괄호 안은 `baseAmount`다.

| 등급 | 실용 물자 풀 | 선행 물자 풀 |
|---|---|---|
| 정착지 | 장작(24) · 곡식(30) · 도구(6) · 철(6) · 가죽옷(6) · 가죽신(5) | 창(4) · 무명옷(5) · 소금(8) · 숯(8, 낮은 가중치) |
| 보(堡) | 정착지 실용품 + 창(6) · 무명옷(7) · 장(8) · 김치(12) · 보존식(10) | 각궁(3) · 은(6) · 숯(10) |
| 진(鎭) | 보 실용품 + 숯(14) · 각궁(4) · 소금(10) · 가축(2, 말 제외) · 군마(1) | 화약(8) · 조총(2) · 사치품(2) |
| 부(府) | 전부. 조총(3) · 화약(12)도 실용 풀에 편입 | 은(10) · 사치품(3)의 가중치 증가 |

창은 보, 각궁과 숯·축사는 진, 조총과 화약 생산은 부에서 열리는 실제 해금 순서를 따른다.
정착지의 숯만은 의도적인 예외다. 두 단계 앞 물자지만 초반 가공과 연료 사정을 크게 완화하는
반가운 군수·연료 지원이므로 낮은 가중치의 선행 물자로 둔다.

소금은 자체 생산 단계가 없는 교역 의존 물자이므로 "한 단계 위"가 아니라 선행 물자로 분류한다.
부(府)는 더 높은 단계가 없으므로 은·사치품이 선행 물자 자리를 대신한다.

각 후보는 `{ resource, baseAmount, weight, minRank, category }`로 등록한다.
초기 가중치는 생존 물자 10~12, 생산 자재 7~9, 군수품 5~7, 은·사치품 3~5 범위에서 시작한다.
같은 하사에서 동일 품목은 중복 추첨하지 않는다.

### 가축과 군마는 다른 물자다

둘 다 축사의 `headcount`로 들어가지만 성격이 다르므로 후보를 나눈다.

| 후보 | 축종 | 성격 |
|---|---|---|
| **군마** | `horse` 고정 | 군수품. 기승 가능 수는 **말을 기르는 축사 수**로 정해진다 (`weapons.ts`) |
| **가축** | `chicken · goat · sheep · pig · cattle` 중 추첨 | 살림. 알·젖·고기·털의 생산 기반 |

즉 **가축 후보에서 말은 빠진다.** 말이 필요하면 군마 후보로만 들어온다.
`MOUNT_NAMES = { horse: '군마' }`이고 기승 수는 `livestock.species === 'horse'`인 축사를 세어 정하므로,
군마 하사는 곧 말 가축 하사이면서 동시에 군사적 의미를 갖는다.

### 받을 그릇이 있어야 한다

가축은 자원이 아니라 **축사의 `headcount`** 다 (`livestock.ts`). 축사는 진(鎭) 승격 후에 지을 수 있고,
수용 한도(`livestockCapacityForStable`)도 있다. 그래서 진 이상에서만 후보가 되며 다른 물자와
달리 조건이 붙는다.

> **그 축종을 받을 빈 자리가 없으면 추첨 풀에서 빠진다.**

판정은 **축종별**로 한다. `acquireLivestock`은 `species`가 같거나 비어 있는 축사만 쓰므로,
소 축사만 가득 차 있다면 군마는 들일 곳이 없어 후보에서 빠지지만 다른 상황일 수도 있다.
같은 함수가 쓰는 조건으로 사전 판정해야 어긋나지 않는다.

이건 §3의 "재고 상태를 보지 않는다" 원칙의 예외이며, 성격이 다르다 —
"부족한 걸 노려 준다"가 아니라 **"받을 수 없는 걸 뽑지 않는다"** 이기 때문이다.
축사를 짓는다고 가축이 나오지는 않는다. 다만 없으면 안 나올 뿐이다.

지급은 `headcount`를 직접 수정하지 않고 기존 `acquireLivestock(state, species, amount)`를 사용한다.
이 함수가 빈 축사 선택, 축종 전환, 수용량 검사와 `unlockedLivestock` 해금을 함께 처리하고,
실패 시 오류 문자열을 돌려주므로 사전 판정이 어긋나도 잘못 지급되지 않는다.

## 3. 추첨 — 랜덤하되 실용품은 보장한다

```
실용 물자 1품목 확정
→ 40% 확률로 실용 물자 1품목 추가
→ 35% 확률로 선행 물자 1품목 추가
→ 물자 지급과 별개로 고유기물 보너스 추첨
```

**노려서 플레이할 수 없게 하는 방법은 "상태를 보지 않는 것"이다.**
숯이 떨어졌다고 숯이 나오면 안 된다. 대신 **각 티어의 모든 항목이 그 시점에 쓸모 있도록** 구성하면
꽝이 없으면서도 예측은 불가능하다. 위 표는 그 기준으로 짰다.

예외는 **받을 수 없는 물자를 뽑지 않는 것**과 **보유 시설로 새 사용처가 열린 물자를 추가하는 것**이다.
전자는 빈 축사가 없는 가축, 후자는 총통 포대 완공 뒤 추가되는 화약이다. 둘 다 현재 재고량을 읽지 않는다.

### 결정성과 시드

현재의 `makeRng(seed + year×9203 + 5)`처럼 **세계 시드와 연차만** 사용한다.
등급과 `tributePaidStreak`는 시드에 섞지 않는다.

- 등급은 후보 풀만 결정한다.
- 연속 납부 수는 승격 조건으로 이미 보상되므로 하사 결과를 다시 강화하지 않는다.
- 면세 교지로 유지된 streak와 실제 납부를 따로 구분할 필요도 없어진다.
- 같은 세계·같은 연도의 결과는 저장/불러오기로 바뀌지 않는다.

세계 생성 시 결과가 결정되어 있어도 정상 플레이에서 미래 결과를 알 방법은 없다.
반대로 등급·재고·streak 같은 가변 상태를 시드에 넣으면 승격 시점이나 재고 조작으로 결과를 바꾸는
여지가 생기므로 사용하지 않는다.

## 4. 고유기물

`state.specialItems` + `SPECIAL_ITEM_DEFS`(기물함)가 이미 돌고 있고,
**해동청**이 "보유만 해도 효과가 붙는 영구 패시브"의 선례다 (`raids.ts`의 `gyrfalconWarningBonus`).
다만 새 항목 추가는 정의표 하나로 끝나지 않는다. 현재는 다음 목록이 각각 명시적으로 관리된다.

- `SpecialItemId`
- `SPECIAL_ITEM_DEFS`
- 새 게임의 `specialItems` 초기값
- `specialEvents.ts`의 구세이브 보정
- `saveLoad.ts`의 허용 목록과 `discoveredSpecialItems` 필터
- 기물별 아이콘

구현하면서 `SPECIAL_ITEM_IDS`를 단일 원본으로 만들고 초기화·저장 보정·도감 필터가 이를 함께 쓰게 한다.
새 기물의 `tradeValue`는 0으로 두어 교역 제시 목록에 나타나지 않게 한다.

효과는 판을 뒤집지는 않되, 2년마다 낮은 확률로 받는 물건답게 보유 사실이 체감되어야 한다.

### 4-1. 1회성 사용

| 기물 | 효과 | 붙일 자리 |
|---|---|---|
| **면세 교지** | 그 해 세공을 납부한 것으로 처리 | §5에서 따로 다룸 |
| **구휼미 어음** | 즉시 곡물 대량 확보 | 기물함에서 사용 |
| **모민 방문(募民 榜文)** | 새 주민 1가구 입주 | 하사 전용 이민 선택지 |

`maybeOfferImmigration`은 계절·일일 확률·쿨다운 검사까지 포함하므로 모민 방문에서 직접 호출하지 않는다.
가족 구성과 수용 후 주거·식량 예측을 공통 헬퍼로 분리하고, 기물을 사용하면 확률 검사 없이
`openGrantedImmigrationChoice`가 수락·거절 선택지를 연다. 사용 시점에 다른 모달이나 전투가 있으면
기물 사용을 막아 소모 후 선택지가 사라지지 않게 한다.

### 4-2. 영구 패시브

| 기물 | 효과 | 붙일 자리 |
|---|---|---|
| **측우기** | **재해 선택지의 성공 확률을 공개** | §6에서 따로 다룸 |
| **권농교서** | 농사 계열 숙련 성장 소폭 + | `gainSkillTick` |
| **의서(醫書)** | 의원 계열 숙련 성장 소폭 + | 〃 |
| **병서(兵書)** | 군사 계열 숙련 성장 소폭 + | 〃 |
| **천리경** | 침략 시 전투 준비 점수 + | `preparationPoints(state, warned)` |

현재 `gainSkillTick`은 `Resident`만 받고 호출부가 많다. 기물마다 호출부를 흩어 고치지 말고
`skillGainArtifactMultiplier(state, job)`를 만든 뒤 공통 숙련 증가 경로가 이를 한 번만 적용하게 한다.
천리경은 우선 정착지 침략 전투의 `preparationPoints(state, warned)`에만 적용하고,
원정·사냥 전투에는 별도 확장 전까지 영향을 주지 않는다.

### 4-3. 설치형

| 기물 | 효과 |
|---|---|
| **사액 현판** | 생산 건물 하나에 영구 귀속. 작업 효율 +25%, 해당 건물의 철거·이전 불가 |
| **지자총통(地字銃筒)** | 하나만 보유. **총통 포대** 1개를 건설할 수 있게 된다 — 불랑기포대의 하위호환 |

#### 사액 현판 — 한 번 걸면 건물과 운명을 같이한다

사액 현판은 왕이 내린 이름과 권위를 건물에 부여하는 물건이다. 편의에 따라 떼어 옮기는 생산 부품처럼
취급하면 격에 맞지 않는다.

- 대상은 **완공된 생산 건물**로 한정한다.
- 한 번 걸면 다른 건물로 옮길 수 없다.
- 현판이 걸린 건물은 플레이어가 철거하거나 이전할 수 없다.
- 설치 전 확인창에서 영구 귀속과 철거 불가를 분명히 경고한다.
- 해당 건물이 습격 등 외부 요인으로 완전히 파괴되면 현판도 소실된다.
  도감 기록은 남고, 보유 수가 0이 되었으므로 이후 하사 추첨에는 다시 들어올 수 있다.

제약이 큰 만큼 효과도 체감되게 한다.

> **해당 건물의 작업 효율 +25%**

초기값은 25%로 두고, 지나치게 강하면 수치만 조정한다. 대장간의 생산품을 바꾸거나 축사의 축종을
바꾸는 등 **건물 내부의 정상적인 운용 변경은 허용**한다. 막는 것은 현판 자체의 이전과 건물 철거다.

상태에는 설치 대상을 별도로 기록한다.

```ts
// GameState
royalPlaqueBuildingId: number | null;
```

#### 지자총통 — 건물 해금형 기물

불랑기포는 **부(府) 승격 후 청원**으로만 얻는다 (`petition.ts`: `minRank: 'bu'`, 명성 70 이상, 명성 −18).
지자총통은 그보다 이른 시점에 **하사로만** 들어와, 화포 방어를 미리 맛보게 한다.
재래식 총통이 신식 불랑기포보다 약한 것은 역사적으로도 자연스럽다.

지자총통은 **한 번만 받을 수 있는 고유기물**이다. 하사될 때 바로 시험 운용할 수 있도록
**화약 6을 함께 지급**한다. 현재 소모량 기준으로 총통을 몇 차례 운용해 볼 수 있는 양이며,
정확한 수량은 `CONFIG`에서 조정한다.

또한 완공된 총통 포대가 하나라도 있으면 이후 실용 하사품 후보에 **화약 묶음**이 추가된다.
재고가 부족할 때만 넣는 것이 아니라 포대의 존재만 조건으로 삼으므로, 화약 재고를 일부러 비워
보상을 유도할 수는 없다.

```ts
if (countBuilt(state, 'chongtongEmplacement') > 0) {
  practicalGrantPool.push({ resource: 'gunpowder', baseAmount: 6, weight: GUNPOWDER_SUPPORT_WEIGHT });
}
```

화약이 매번 확정 지급되는 것은 아니지만, 생산 기술이 열리기 전에도 조정의 후속 군수 지원으로
포대를 계속 운용할 가능성이 생긴다.

| | 불랑기포대 (기존) | **총통 포대** (신규) |
|---|---|---|
| 획득 | 부(府) 청원, 명성 소모 | **하사 기물** |
| 방어도 | +40 | 낮게 (절반 안팎) |
| 전투 방어 배율 | `CONFIG.raid.cannonBattleMult` = 1.2 | 더 낮은 별도 배율 |
| 사전포격 | 참여 | 참여하되 위력 낮음 |
| 화약 | 교전마다 소모 | 동일 (소모는 유지) |

**배치 상한에 새 상태 필드가 필요 없다.** 불랑기포대는 `cannonPlacementsUsed(state) >= state.cannonsGranted`로
막는데, 총통 포대는 단 하나뿐인 기물의 보유 여부를 상한으로 쓰면 된다:

```ts
chongtongPlacementsUsed(state) >= Math.min(1, state.specialItems.jijaChongtong)
```

지자총통은 포대를 지을 때 소비되지 않고 보유 상태로 남는다. 포대가 파괴되거나 철거되어도
기물함의 지자총통을 바탕으로 한 번만 다시 지을 수 있다.

**구현 주의**: 전투 쪽 `cannonBattleMult`와 사전포격 판정이 지금은
`countBuilt(state, 'cannonEmplacement')` 하나만 본다 (`battles.ts`, `tacticalBattle.ts`).
총통 포대를 **같이 세는 대신 가중치를 달리 주는** 형태로 고쳐야 한다.
같은 배율을 그대로 쓰면 "저위력"이 성립하지 않는다.

에셋은 초기에 불랑기포대 스프라이트를 공유해도 무방하다 (같은 계열의 포대).
전용 스프라이트는 후속으로 미룬다.

### 4-4. 장착형 — 고유 무기 (신규 계열)

가장 새로운 메커니즘이자 가장 재미있는 자리다.

- **계열은 기존과 공유**한다 (창·각궁·조총 중 하나) — 새 무기 종류를 만들지 않는다
- 같은 계열의 일반 무기보다 **효과가 강하다**
- **특수 주민이 있으면 우선 장착**, 없으면 일반 수비병·사냥꾼에게 지급
- **전투 중 장착자가 죽으면 기물도 소실된다**

마지막 규칙이 핵심이다. 강한 무기를 쥐어 주고 싶지만 잃을 수 있으니, **누구에게 언제 쥐어 줄지**가
실제 결정이 된다. 아껴서 창고에 두면 아무 일도 없고, 꺼내 쓰면 위험을 진다.

**구현 주의**: 현재 무기는 `weaponAssignments: Partial<Record<number, CombatWeaponId>>` 로
**종류만** 저장하고 개별 인스턴스를 추적하지 않는다. 고유 무기는 별도 필드가 필요하다.

```ts
// GameState
artifactWeapon?: { item: SpecialItemId; residentId: number | null };
```

장착자 사망 처리는 여러 전투 사상자 정산부에 각각 붙이지 않는다. 모든 사망이 모이는
`killResident(state, resident, ..., combatDeath)`에서 `combatDeath`일 때 장착 기물과 주민 id가
일치하면 기물을 소실시킨다. 비전투 사망 때의 회수 여부는 고유 무기별 규칙으로 별도 지정한다.

## 5. 면세 교지 — 두 시점에서 쓸 수 있다

세공은 **봄 첫날 공지 → 겨울 첫날 수거**다. 면세 교지는 그 사이 어느 쪽에서든 쓸 수 있어야 한다.
이미 산삼·해동청 진상으로 얻는 `state.tributeWaivers`와 겨울 자동 면제 경로가 있으므로
별도의 면세 시스템을 만들지 않고 같은 처리 헬퍼를 사용한다.

| 시점 | 경로 |
|---|---|
| 미리 (공지~수거 전) | 기물함에서 사용 → 그 해 세공은 납부 처리 |
| 수거 당일, 준비를 못 했을 때 | **세공 모달에 선택지 하나 추가** — "교지를 내보인다" |

두 경로 모두 결과는 같다:

- `releaseTributeReserve(state)`로 세공고에 잠긴 물자를 즉시 해제
- 면세 교지 1개 소모
- `tribute.paid = true`, `resolved = true`
- `tributePaidStreak += 1` — **연속 납부가 끊기지 않는다** (승격 조건에 직결되므로 중요)
- `tributeFailStreak = 0`
- 명성은 오르지 않는다
- 해당 연도가 짝수여도 새 하사품은 지급하지 않는다

조정이 공식적으로 면제한 해이므로 승격용 성실도는 유지하지만, 실제 공물을 받지 않은 조정이
다시 답례품을 보내지는 않는다. 산삼·해동청으로 얻는 기존 면제권도 같은 규칙을 유지한다.

```ts
resolveTributeWaiver(state, { consumeItem: 'tributeDecree' });
```

기물함에서 미리 사용할 때와 수거 모달에서 사용할 때 모두 이 헬퍼를 호출한다.
이미 올해 세공이 해결되었거나 아직 공지가 오지 않은 상태에서는 사용할 수 없다.

### 산삼 면제권과의 우선순위

두 면제 수단은 **선택하는 시점이 다르다**. 산삼은 발견 즉시 진상 여부를 정하고,
교지는 그 뒤 아무 때나 꺼낼 수 있다. 따라서 **산삼이 우선**이다.

| 상황 | 결과 |
|---|---|
| 산삼 면제권 보유 + 올해 미해결 | 겨울 수거일에 **산삼이 먼저 자동 소모** — 올해 면제 |
| 산삼으로 면제받은 해 | **교지 사용 불가** (이미 `resolved`) |
| 교지를 이미 쓴 해에 산삼 진상 | 면제권은 재고로 남아 **다음 해 세공이 면제된다** |

**앞의 둘은 이미 성립한다.** `maybeCollectTribute`는 겨울에 매일 검사하며
모달을 열기 전에 `tributeWaivers`를 소모하므로 산삼이 자동으로 앞선다.
자동 면제가 `resolved = true`로 만들므로 §5의 기존 가드가 교지 사용을 그대로 막는다.

세 번째도 **새 로직이 필요 없다.** `tributeWaivers`는 연도에 묶이지 않은 재고 카운터라,
올해가 이미 해결된 상태면 소모되지 않고 남아 다음 겨울 수거일에 쓰인다.

필요한 것은 **진상 시점의 안내 문구**뿐이다. 지금은 면제권이 언제 쓰일지 알려 주지 않으므로,
그해 세공이 이미 해결된 상태에서 진상하면 다음 해가 면제된다는 것을 로그에 명시한다.

```
"산삼을 진상했습니다. 올해 세공은 이미 면제되어, 내년 세공이 면제됩니다."
```

"꼬박꼬박 냈더니 한 해 쉬어 가라"는 서사가 이번 개편의 불만을 정확히 갚아 준다.

## 6. 측우기 — 해마다 달라지는 재해 확률을 관측한다

날씨를 미리 맞히는 기물로 만들지는 않는다. 측우기와 함께 운용하는 관측 장부 덕분에
**그해의 기후 경향과 재해 선택지의 실제 성공 확률을 안다**는 효과로 삼는다.

현재 이른 서리의 `wait-harvest` 성공률 58% 하드코딩은 제거한다.
연간 기후와 실제 일일 날씨는 선행 문서 `DESIGN-2026-07-28-annual-climate-weather.md`에서 먼저 구현한다.
재해 발생 가중치와 선택지 성공률은 그 시스템의 기후값을 함께 사용한다.

```ts
interface AnnualClimate {
  temperatureAnomaly: number;   // -1 한랭 ~ +1 온난
  precipitationAnomaly: number; // -1 건조 ~ +1 다습
  storminess: number;           // -1 잔잔 ~ +1 거침
}
```

이 값은 이미 그해 비·눈·서리·혹한 일수에 반영되어 있다. 별도 상태로 저장하지 않고
`seed + year`에서 결정적으로 다시 계산하므로 저장/불러오기로 바뀌지 않으며,
한 해 안에서 모달을 닫았다 다시 열어도 같은 확률을 사용한다.

### 이른 서리 첫 적용

```ts
earlyFrostClearsChance =
  clamp(
    CONFIG.disasters.earlyFrost.baseClearChance
      + annualClimate.temperatureAnomaly * CONFIG.disasters.earlyFrost.temperatureEffect,
    CONFIG.disasters.earlyFrost.minClearChance,
    CONFIG.disasters.earlyFrost.maxClearChance,
  );
```

초기 수치는 평균 57%, 범위 **42~72%**로 둔다. 따뜻한 해에는 서리가 걷힐 가능성이 높고,
한랭한 해에는 낮다. 숫자는 이벤트 코드에 직접 쓰지 않고 모두 `CONFIG.disasters`에 둔다.

- `harvest-early` — 조기 수확, 예상 소출의 약 절반 확보
- `wait-harvest` — 그해 확률로 정상 수확 성공 여부 판정, 실패 시 소출 대부분 손실

측우기가 없으면 기존처럼 정성적인 설명만 보인다.

```
기다린다 → "서리가 걷히면 정상 수확하지만, 버티지 못하면 소출 대부분을 잃습니다."
```

측우기가 있으면 같은 판정 함수가 계산한 실제 값을 문구에 넣는다.

```
기다린다 → "올해 관측상 서리가 걷힐 가능성 64%. 버티지 못하면 소출 대부분을 잃습니다."
```

### 재해 확률의 단일 원본

재해별 발생 가중치와 선택지 성공률을 한 모듈에 등록한다.

```ts
disasterOccurrenceWeight(state, eventId)
disasterChoiceChance(state, eventId, optionId)
```

- 이벤트 후보 추첨은 `disasterOccurrenceWeight`를 사용한다.
- 실제 선택 결과와 측우기 UI는 **같은** `disasterChoiceChance`를 사용한다.
- 재해별 수식과 최솟값·최댓값은 `CONFIG.disasters`에 둔다.
- 재해별 salt를 독립적으로 두어 새 재해를 추가해도 기존 연도의 확률이 바뀌지 않게 한다.

앞으로 가뭄은 `precipitationAnomaly`, 황충은 온도·강수 조합과 재해 전용 연차 변동을 사용한다.
새 재해가 자동으로 적용되는 것은 아니며, 추가할 때 발생 가중치와 선택지 확률을 이 등록부에
명시해야 한다. 이렇게 해야 실제 날씨, UI 문구와 재해 판정이 서로 다른 기후를 쓰는 일을 막을 수 있다.

## 7. 희소성 규칙

- 고유기물은 **하사로만** 얻는다 (교역·이벤트 불가)
- 실용·선행 물자를 모두 지급한 뒤 **독립적으로 12% 보너스 추첨**
- 4회 연속 기물을 받지 못했다면 5번째 적격 하사에서 기물 확정
- 천장 진행도는 `courtGrantArtifactMisses`에 저장하여 저장/불러오기로 초기화되지 않게 한다
- **이미 가진 고유기물은 추첨에서 제외** — 중복은 실망만 준다
- 1회성 기물은 소진 후 다시 나올 수 있다
- 한 번의 하사에서는 고유기물 최대 1개
- 모든 조정 하사 전용 기물은 `tradeValue: 0`으로 두어 교역할 수 없다

면세 교지로 넘긴 해에는 하사품 자체가 없으므로 기물 추첨도 하지 않고 천장 진행도도 증가하지 않는다.
12%로 2년마다 추첨하면 장기간 하나도 보지 못할 수 있으므로 숨은 천장을 둔다. 플레이어에게
정확한 수치나 진행도를 공개하지 않아 특정 기물을 기다리는 운영 목표가 되지 않게 한다.

## 8. 구현 순서

먼저 `DESIGN-2026-07-28-annual-climate-weather.md`의 W1~W4를 완료해 연간 기후가 실제 날씨로
표현되게 한다. 아래 G 단계는 그 뒤에 시작한다.

| 단계 | 내용 | 검증 |
|---|---|---|
| G1 | 실용 물자 확정 + 추가 실용·선행 물자 독립 추첨 + 완만한 연차 스케일 | 등급별 후보·수량·결정성 |
| G1b | 가축 하사 — `acquireLivestock` 재사용 | 축사 없음·만원 시 풀 제외, 축종 해금 |
| G2 | `SPECIAL_ITEM_IDS` 단일 원본 + 초기 상태·구세이브·도감 보정 | 새 게임·구세이브 로드 |
| G2b | 물자와 독립된 기물 12% 추첨 + 중복 제외 + 5회 천장 | 분포·천장·불러오기 |
| G3 | 구휼미 어음 · 면세 교지 + 공통 `resolveTributeWaiver` | 예약 해제·streak·무명성·무하사 |
| G3b | 모민 방문 + `openGrantedImmigrationChoice` | 계절·일일 확률 우회, 모달 충돌 차단 |
| G4 | 선행작업의 `AnnualClimate`을 재해 발생·선택 확률에 연결 + 측우기 UI | 연도별 변동·실제 날씨 연계·문구와 판정 일치 |
| G5 | 숙련 계열 영구 패시브 + 공통 배율 훅, 천리경 | 직업군별 적용·원정 비적용 |
| G6 | 사액 현판 — 영구 귀속, 철거·이전 차단, 외부 파괴 시 소실 | 설치 확인·효율·파괴 |
| G7 | **지자총통 + 총통 포대** — 단일 배치, 최초 화약, 화약 하사 풀, 전투 가중치 분리 | 불랑기와 위력 차·후속 군수 |
| G8 | 고유 무기 인스턴스 + `killResident` 소실 훅 | 장착·전사·비전투 사망 |

**첫 구현 범위는 G1~G4로 제한한다.** 여기까지면 하사품 개편의 핵심인 실용 보상, 낮은 확률의 기물,
면세 교지, 측우기까지 실제 플레이에서 확인할 수 있다. 사액 현판·총통·고유 무기는 각각 별도
검증이 필요한 확장 단계로 둔다.

G7은 전투 계산에 손이 닿는다. `cannonBattleMult`, 화약 소비, 사전포격이 지금 불랑기포대만 세므로
두 포대의 가중치와 화약 소모 우선순위를 하나의 포병 계산 헬퍼로 통합해야 한다.

G8은 새 장비 인스턴스 상태가 필요하지만 사망 처리는 중앙 `killResident`에 연결하여 전투 종류마다
별도 훅을 두지 않는다.

## 9. 열어 둔 판단

- **고유 무기의 소실 빈도**: 특수 주민이 전투에서 죽는 빈도에 따라 체감이 크게 갈린다.
  너무 자주 죽으면 아예 안 쓰게 되어 사장되고, 안 죽으면 리스크가 장식이 된다.
  보수적으로 시작해 실제 전투 로그를 보고 조정한다.
- **연차별 기후 변동 폭**: 이른 서리는 우선 42~72%로 시작한다. 선택이 사실상 강제되거나
  측우기가 없어도 답이 명백해지면 범위를 좁힌다.
- **실용 물자 기준량**: 표의 기준량과 1.8배 상한은 첫 분포 테스트와 5·10년차 세이브에서 조정한다.
- **사액 현판의 효율 폭**: 영구 귀속과 철거 불가를 감수할 가치가 있도록 우선 +25%에서 시작한다.
