## 0. 이번 범위의 결과

새 개척 설정에서 산지를 선택할 수 있다. 산지는 지도 안쪽까지 능선이 뻗고, 평원보다 강·비옥지·일반
수맥이 적다. 대신 큰 숲, 접근 가능한 산자락 노두, 지하 광맥, 사냥 서식지가 많다. 소형·중형·대형
모두 같은 지역 정체성을 유지하며 같은 시드+크기+지역은 같은 결과를 만든다.

시작 불능을 막기 위해 정착지 주변 평탄지, 시작 수맥 하나, 도달 가능한 근거리 돌·철, 가까운 사냥
서식지 하나는 모든 난이도·크기에서 계속 보장한다.

## 1. 확정 지역 프로필

| 축 | 평원 | 산지 초기값·목표 |
|---|---|---|
| 산 | 동·북 둘레 중심 | 둘레 산 + 중앙 안전 반경 밖 내부 능선 다수 |
| 강·비옥지 | 1~3칸 강, 강변 비옥지 기준 | 강 폭 1~2칸, 비옥지 확률 약 절반 |
| 평지 | 기준 | 산·숲 증가만큼 감소 |
| 숲 | 기준 blob 26 | 기준 blob 약 38~40, 큰 연결 숲 우선 |
| 표면 광상 | 산자락 25%, 철 50% | 산자락 약 38%, 철 약 60% |
| 일반 수맥 | 기준 | 개수 약 65%, 반경·용량 약 75%; 시작 수맥은 기준 유지 |
| 지하 광맥 | 기준 | 광종별 개수 약 1.1배, 반경 약 90%, 용량 약 1.4배 |
| 사냥 서식지 | 난이도 확률 | 난이도 확률×1.2(상한 0.98) + 숲 증가 |

수치는 첫 표본값이며 단일 시드가 아니라 여러 시드·세 크기 합산 지표로 판정한다. 목표 방향을 못
만족하거나 통행 가능 면적이 과도하게 줄면 프로필 수치를 조정하되 평원 생성 경로는 건드리지 않는다.

## 2. 데이터·결정론 계약

1. `generateMap(seed, dimensions, region = 'plains')`로 확장한다. 평원 분기의 기존 난수 호출 순서와
   수식은 그대로 유지해 현재 중형·크기별 평원 결과를 보존한다.
2. `normalizeNewGameOptions()`는 `plains|mountain`만 보존하고 호수·해안은 S4/S5까지 평원으로
   안전 보정한다.
3. 지하 자원 API는 마지막 선택 인자로 `region = 'plains'`를 받는다. 수맥·광맥 캐시 키에도 region을
   반드시 포함해 같은 시드·치수의 평원과 산지가 기하를 공유하지 않게 한다.
4. 지도·배치·채광·급수·지하 레이어·저장 정규화의 모든 지하 자원 호출은
   `state.worldSetup.region`을 전달한다. 구 저장 마이그레이션은 명시적 평원을 사용한다.
5. 산지 서식지 확률 보정은 `worldSetup.effective.habitatChance`에 스냅샷으로 저장한다. 이미 시작한
   판은 이후 기본 수치가 바뀌어도 저장된 확률을 유지한다.
6. 기존 v57 저장은 전부 평원이므로 스키마를 올리지 않는다. 새 산지 저장은 region과 서로 다른
   수맥·광맥 잔량 배열을 함께 저장한다.

## 6. 완료 기준

- 산지가 세 지도 크기에서 선택·생성·저장되며 평원 결과는 변하지 않는다.
- 다중 시드 합산으로 산지는 평원보다 내부 산·숲·표면/지하 광물·서식지 수용력이 많고,
  평지·강·비옥지·일반 수맥이 적다.
- 모든 산지 판에 시작 수맥, 근거리 돌·철, 가까운 서식지와 충분한 중심 통행 가능 면적이 있다.
- 지하 레이어·우물·채광갱이 산지 기하와 같은 region을 읽고 core·빌드·실화면 검증이 통과한다.
