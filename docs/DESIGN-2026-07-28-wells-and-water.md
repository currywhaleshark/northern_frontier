# 우물과 급수 — 설계

> **계획 상태:** 미착수
> **상태 갱신:** 2026-07-29 — 우물과 급수 체계는 설계만 기록됐고 구현은 시작되지 않았다.

- 작성일: 2026-07-28
- 발단: 화재 재해의 선행 조건 (`DESIGN-2026-07-28-disasters.md` §3-9) + 내륙 논의 길 열기
- 범위: 수맥·수위 모델 + 우물 + 급수 판정 + 농수로 + 화재 재해 해금
- 연관: 재해 문서(가뭄·화재), 기후 문서(강수 회복), 특수 주민 허생
- 구현: 다른 작업자 인수인계 전제

## 0. 확정된 방향

| 결정 | 내용 |
|---|---|
| 지하수 총량 | 월드 생성 시 결정적으로 확정 (시드 함수 — 광상 패턴과 동일 철학) |
| 고갈 | **수위 모델** — 마르는 게 아니라 낮아지고, 강수로 회복 |
| 수맥 가시성 | 전용 레이어. **범위(있다/없다)는 누구나** 보고, **농담(어디가 깊은지)은 허생만** 본다 |
| 일상 급수 | 커버리지 부기 — 주민이 물을 매일 길어 나르지 않는다 |
| 물리적 운반 | **화재 진화에만** — 주민이 우물·강에서 물을 퍼 나른다 |
| 농수로 | 강에 연결된 수로가 내륙 논을 연다. 물레방아·나루터는 해당 없음 |

## 1. 수맥 — 생성과 기하

### 1-1. 생성

월드 시드에서 결정적으로 수맥 지대 몇 곳을 심는다. 광상(`setMineralDeposit`)과 같은
철학이지만, 칸 단위가 아니라 **여러 칸에 걸친 범위**다.

```ts
// 시드만으로 재계산 가능 — 기하는 저장하지 않는다
interface AquiferVein {
  id: number;
  cx: number; cy: number;   // 중심 (가장 깊은 곳)
  radius: number;           // 범위 반경 (칸)
  capacity: number;         // 중심 기준 최대 수량
}
export function aquiferVeins(seed: number, mapW: number, mapH: number): AquiferVein[];
```

칸별 풍부도는 중심에서 멀수록 옅어진다 — 등고선 모양.

```ts
richnessAt(vein, x, y) = capacity × falloff(dist(x,y, cx,cy) / radius)
// falloff: 1(중심) → 0(가장자리), 부드러운 감쇠
aquiferRichnessAt(seed, x, y) = 겹치는 수맥 중 최댓값
```

- 개수·크기는 지도 크기에 비례 (초기값: 72×72 기준 4~6곳, 반경 4~7칸)
- 강 바로 옆은 우물이 무의미하므로(강 인접 건물은 자체 급수) 수맥 중심이 강에서
  일정 거리 이상 떨어지도록 배치 가중치를 준다 — 내륙에서 쓸모 있게

### 1-2. 가시성 — 두 단계

| 조건 | 보이는 것 |
|---|---|
| 기본 (누구나) | 수맥 **범위** — 균일한 연파랑. "여기 어딘가에 물이 있다" |
| **허생 재촌** | **농담(濃淡)** — 풍부도에 비례한 파랑 짙기. 짙은 곳 = 중심 = 깊은 수맥 |

허생 없이는 범위 안 어디가 중심인지 알 수 없다 — 파 보는 것이 도박이 된다.
허생은 필수가 아니라 **정보 우위**다 (특수 주민은 확률 등장이므로 필수 조건으로 걸지 않는다).

허생의 소개문(`specialResidents.ts` geomancer)에 수맥 정밀 관측을 추가한다.
"지팡이로 산맥을 짚는" 지관이 수맥도 짚는 것은 인물 설정 그대로다.

### 1-3. 수맥 레이어 UI

- `uiPrefs`에 `showAquiferLayer` 토글 추가 (기존 `showResidentJobMarkers` 패턴)
- **우물 배치 모드에서는 자동 표시** (채광장 배치 시 작업 반경 표시와 같은 관례 —
  `renderer.ts`의 `drawMineWorkRange` 참조)
- 렌더러는 `aquiferRichnessAt`와 허생 재촌 여부만 읽는다

## 2. 수위 모델

수맥 기하는 불변, **수위만 상태**다.

```ts
// GameState — 세이브 +1, 구세이브는 전 수맥 만수위로 시작
aquiferLevels: number[];   // 수맥 id 순, 0 ~ capacity
```

### 일일 갱신 (자정)

```
회복 = 기본회복 × (1 + 강수보정)     // 비 오는 날 추가, 기후 문서의 precipitationAnomaly 반영
소비 = 이 수맥에 연결된 우물들이 공급한 수요 합
수위 = clamp(수위 + 회복 - 소비, 0, capacity)
```

- **가뭄 재해 중에는 회복 = 0** (재해 문서 §3-4와 연동) — 가뭄이 강가(보로 완화)와
  내륙(수위 하락)을 다르게 때린다
- 우물 출력 = `min(1, 수위 / 안전수위)` — 수위가 낮으면 급수율이 떨어질 뿐 죽지 않는다.
  비가 오면 돌아온다. 영구 고갈 없음
- 같은 수맥 위 우물 여럿이면 수위를 공유한다 — 우물을 늘려도 물이 늘지는 않는다

## 3. 우물 건물

| 항목 | 값 |
|---|---|
| 배치 | `land`, **풍부도 > 0인 칸만** (레이어가 보이므로 헛 배치 방지) |
| 비용 | 목재·돌 소량. 정착지 등급부터 (역사적으로 우물은 마을의 기본) |
| 산출 | `richnessAt(칸) × 수맥 수위율` — 같은 수맥이라도 중심에 판 우물이 강하다 |
| 급수 반경 | R칸 (초기 6) 내 건물에 급수 연결 |
| 슬롯 | 없음 (무인) |

배치 미리보기에 예상 산출을 표시한다 — 허생이 없으면 "물이 있는 땅입니다" 수준,
허생이 있으면 농담이 보이므로 스스로 판단 가능.

## 4. 급수 판정 — 커버리지 부기

**주민이 일상 급수를 길어 나르지 않는다.** 매일 자정에 장부만 정리한다.
(20명이 매일 물 길으러 왕복하면 에이전트 트래픽과 노동 시간이 무너진다 — 물 긷기는
생활의 일부로 추상화하고, 물리적 운반은 화재 진화에만 쓴다)

### 4-1. 공급 판정

건물이 다음 중 하나면 급수 연결:

1. 강 상하좌우 인접 (`hasAdjacentRiver` 재사용) — 자체 급수, 수맥 무관
2. 우물 반경 R 내 — 해당 우물의 수맥에서 차감

수요 총합이 우물 출력 합을 넘으면 **연결률**(0~1)이 내려간다. 주택 우선, 생산 건물 후순위.

### 4-2. 수요표

| 소비자 | 수요 | 근거 |
|---|---|---|
| 주택 | 입주자 합 × 계수 (`bedShare` 재사용 — 아이는 반몫) | 가구원수 비례 |
| **가죽공방** | 대량 | 무두질은 실제로 물을 많이 쓰는 공정 |
| 옹기가마 | 중간 | 반죽 |
| 진료소 | 중간 | 위생 |
| 축사 | 두수 비례 | 음수 |
| 그 외 생산 | 0 또는 소량 | 타입별 `CONFIG.water.demand` 표 |

### 4-3. 미급수 효과 — 경성 생존 수치는 만들지 않는다

갈증-사망 축은 넣지 않는다 (죽음의 나선 하나 추가일 뿐). 대신:

| 대상 | 효과 |
|---|---|
| 미급수 주택 | 사기 소폭 하락 + **질병 확률 가중** (역병 강화와 연동 — 급수는 위생이다) |
| 미급수 물소비 생산건물 | 효율 절반 |
| 화재 | 반경 내 급수원(우물·강) 없으면 진화 불가 (§6) |

기존 세이브·초반 정착지가 우물 없이도 즉사하지 않게, 효과는 전부 "없으면 아쉬운" 수준에서
시작하고 수치는 `CONFIG.water`에 모은다.

## 5. 농수로

강물을 끌어 내륙에 논을 연다. **논만이다** — 물레방아·나루터는 `terrain === 'river'`를
직접 검사하므로 수로의 영향을 받지 않는다 (배제 처리가 공짜).

- 구간형 건물 (제방·목책 패턴). 통행 가능
- 유효 조건: 수로망이 BFS로 **강에 닿아야** 한다. 끊긴 수로는 마른 도랑
- 논 판정 확장: `isPaddyEligibleTile`의 강 인접에 "유효 수로 인접"을 추가
  ([buildings.ts:601](src/game/buildings.ts:601) — 비옥지 요건은 유지. 내륙의 비옥지
  조각을 수로로 살리는 그림)
- 가뭄 중 수로급 논은 강급 논과 동일하게 페널티 — 보(洑) 반경만이 완화 (재해 문서 §3-4)
- 겨울 결빙·해빙 홍수와의 상호작용은 1차에서 다루지 않는다 (열어 둔 판단)

## 6. 화재 — 보류 해제

재해 문서 §3-9의 선행 조건이 이 문서로 충족된다. 재해 등록부(`disasterOccurrenceWeight`)에
등록하고, 지연 판정 기반(D0) 위에서 돈다.

### 6-1. 발화

- 발화원 가중치: 대장간·숯가마·옹기가마·염초장 > 주택(겨울 난방철) > 기타
- 발생 가중치: 건조한 해(`precipitationAnomaly` 낮음) + 무강수 연속 구간에 정렬
- 염초장 화재는 화약 재고가 있으면 피해 가중 (보관량 비례 폭발 — 소량이면 그냥 화재)

### 6-2. 확산과 진화 (일일 누적형)

```
매 서브틱: 불붙은 건물 → 인접 N칸 내 건물로 확산 판정 (바람은 1차 제외)
진화 속도 = 물을 나르는 주민 수 × 계수
불이 이기면: 건물 전소(damageBuildings 패턴, 복구 몫 큼) 후 인접으로
주민이 이기면: 진화 완료, 부분 파손으로 종료
```

- **진화 인력**: 근처의 일할 수 있는 주민이 자동 투입 — 개간 crew 배정 로직
  (`assignClearingCrews`)과 같은 "현장당 상한 + 가까운 순" 패턴 재사용
- **물 운반**: 주민이 가장 가까운 급수원(우물 또는 강)과 화재 현장을 왕복.
  급수원이 멀수록 진화가 느리다 — **우물의 배치가 소방 인프라가 된다**
- 우물에서 퍼는 물은 수맥 수위를 소량 차감 (가뭄 중 화재가 최악인 이유)
- 급수원이 반경 내에 없으면 진화 불가 — 다 탈 때까지 번진다
- 시각효과: 불꽃·연기 오버레이 (렌더러), 진화 주민은 물동이 운반 태스크 라벨

### 6-3. 선택지는 없다

화재는 대비(우물 배치·건물 간격)와 대응(진화 인력)의 재해다. 모달 선택지 없이
경보와 로그로만 알린다 — 설해와 같은 "대비했으면 버티는" 계열.

## 7. 구현 순서

| 단계 | 내용 | 의존 |
|---|---|---|
| U1 | `aquiferVeins`·`richnessAt` + 수위 상태 + 일일 갱신 + 세이브 +1 | 기후 W1 (강수 보정) |
| U2 | 우물 건물 + 배치 검증 + 산출 | U1 |
| U3 | 급수 판정 부기 + 수요표 + 미급수 효과 | U2 |
| U4 | 수맥 레이어 렌더 (범위/허생 농담) + 배치 모드 자동 표시 | U1 |
| U5 | 농수로 + 논 판정 확장 | — (U1과 독립) |
| U6 | 화재 재해 (발화·확산·진화) | U3, 재해 D0 |

U5(농수로)는 수맥과 독립이라 병렬 가능. U6(화재)만 재해 문서의 D0에 걸린다.

## 8. 열어 둔 판단

- 수맥 개수·반경·capacity 초기값 — 지도를 몇 개의 우물 생활권으로 나눌 것인가
- 안전수위 곡선 — 수위 몇 %부터 급수율이 떨어지기 시작하는지
- 미급수 질병 가중의 폭 — 역병 강화(재해 D7)와 같이 조정
- 겨울의 수로·우물 결빙 여부 — 1차 제외, 체감 봐서 추가
- 화재 확산에 바람(폭풍성) 반영 여부 — 1차 제외
- 허생 부재 시 대체 정보 수단(무당의 기우제? 시추 시도?) — 현재는 "범위만 보고 도박"으로 충분한지 관찰
