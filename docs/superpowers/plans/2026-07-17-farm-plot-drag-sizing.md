# 논밭 크기 지정 계획: 드래그로 넓히는 경작지 — 면적 비례 노동과 농우(農牛)

> 역사 계획 (2026-07-18): 체크박스와 후속 항목은 작성 시점 기록이다. 현재 상태는
> [UI 재구성 릴리스 후보](../../release-candidates/2026-07-ui-reorganization.md)를 기준으로 한다.

> **For agentic workers:** 핵심 방향(드래그 크기 지정, 최대 3×3, 면적 비례 소출·필요 인원,
> 인력 부족 시 파종·수확 미완 손실, 농우 제공 옵션)은 사용자 확정. 세부 수치(필요 인원 공식,
> 농우 배수)와 §7의 미결 사항은 구현 중 CONFIG 시작값으로 제안하되 튜닝 대상으로 표시한다.
> 구현은 superpowers:subagent-driven-development 또는 superpowers:executing-plans로
> Phase 단위 진행한다.

**Goal:** 지금 밭·논은 1×1 건물을 한 칸씩 짓고 한 칸씩 작물을 바꿔야 하는 구조라, 농지가
10칸을 넘어가면 작물 변경·농부 배정이 전부 반복 클릭이 된다. 이를 **드래그로 크기를 지정하는
하나의 경작지(최대 3×3)**로 바꾼다 — 면적이 넓을수록 소출과 필요 인원이 함께 늘고, 필요
인원보다 농부가 적으면 **봄 안에 파종을 못 끝내거나 서리 전에 수확을 못 끝내 손실**이 난다.
여기에 축사의 소를 **농우로 제공하는 옵션**을 열어 경작 효율을 끌어올릴 수 있게 한다.
관리 부담은 줄고, "몇 칸을 몇 명으로 부칠 것인가 + 소를 밭에 내줄 것인가"라는 결정이 남는다.

**확정된 설계 결정 (2026-07-17):**
- **논밭은 드래그로 크기를 지정해 짓는다.** 상한은 **3×3 (9칸)**.
- **소출과 필요 인원은 면적에 비례**한다. 배정 농부가 필요 인원보다 적으면 봄 파종이
  덜 끝나거나(심은 만큼만 자란다) 가을 수확이 덜 끝난 채 서리를 맞아(기존 동결 손실 활용)
  실질 손실이 발생한다.
- **소(축사)를 농경용으로 제공하는 옵션**을 추가한다. 농우가 배정된 경작지는 효율이 오른다.

---

## 1. 역사적 밑그림 (설계의 근거)

- **조선 농사는 소가 반이었다.** 우경(牛耕)은 심경(깊이갈이)을 가능하게 해 소출을 크게
  좌우했고, 소 없는 농가는 소 있는 집에 품을 지어 소를 빌렸다. "농우 제공"은 축산과 농업을
  잇는 고증 그대로의 장치다.
- **북관의 짧은 농사철.** 함경도는 무상(無霜) 기간이 짧아 파종과 수확의 시한이 남쪽보다
  훨씬 빡빡했다 — "봄 안에 못 심으면, 서리 전에 못 거두면 그해 농사는 끝"이라는 압박이
  이 지역의 실제 조건이다. 이미 있는 겨울 서리 동결(§2)과 조상(早霜) 사건이 이 서사를
  받치고 있다.
- **전(田)의 단위.** 실제 경작지는 한 뙈기 단위의 면(面)이지 점(點)이 아니다. 드래그
  경작지는 시각적으로도 "마을 어귀의 논배미·밭뙈기"에 가까워진다.

## 2. 현재 코드의 출발점 (2026-07-17)

- **밭(field)·논(paddy)은 1×1 건물, 농부 슬롯 1.** `WORKER_SLOT_CONFIG`(workerSlots.ts)에
  타입별 고정 슬롯. 건물마다 `fieldGrowth`(0~100), `cropId`, `queuedCropId`를 갖고
  농부가 붙어 성장(`growPerSubtick`)·수확(`harvestPerSubtick`)을 굴린다(agents.ts
  `farmerTick`).
- **발자국(footprint)은 타입별 고정 1 또는 2.** `buildingFootprintSize(type)`
  (buildings.ts:290) — 건물 인스턴스가 아니라 **타입**이 크기를 결정한다. 이 함수를 쓰는
  곳: agents, claimZones, exploration, passage, raids, foreignSiteActivity,
  selectionActions, simulation, renderer. **이 시그니처를 인스턴스 기반으로 바꾸는 것이
  이 계획의 가장 넓은 공사다.**
- **배치는 클릭 1회.** App.tsx `placingType` → `tryPlaceBuilding(state, type, x, y)`.
  GameCanvas의 드래그는 현재 화면 이동 전용(DRAG_THRESHOLD로 클릭과 구분).
- **서리 동결 손실이 이미 있다.** 겨울 시작 시 월동 작물이 아닌 `fieldGrowth > 1`인
  밭은 전부 0으로 리셋되고 "거두지 못한 곡식이 서리에 얼어붙었습니다" 로그가 뜬다
  (simulation.ts:794). **수확 미완 손실은 새 메커니즘이 아니라 이 기존 규칙이 면적
  스케일과 만나며 자연히 커지는 것이다.** 특수 사건 조상(earlyFrost)도 같은 결을 쓴다.
- **소의 농사 보너스는 이미 있으나 전역 패시브다.** `cattleFarmWorkMultiplier`
  (livestock.ts:204) — 소 있는 축사 1곳당 +8%, 최대 +24%가 모든 밭의 성장·수확에
  자동 적용된다. 플레이어 결정이 개입하지 않는다. 이 계획에서 **명시적 농우 배정으로
  대체**한다(§5).
- 작물 정의(crops.ts)는 `plantSeasons`/`growSeasons`/`harvestSeasons`를 이미 구분하고
  있어 "봄 파종 시한"의 재료가 갖춰져 있다. 비옥지 보너스는 현재 **기준 칸 1곳만** 검사한다
  (agents.ts:1055) — 다칸 경작지에서는 칸별 평균으로 바꿔야 한다.
- 저장 스키마는 v21(`CURRENT_SCHEMA_VERSION`). `rebuildBuildingFootprints`(buildings.ts:337)가
  로드 시 발자국을 재구성하므로 마이그레이션 부담이 적다.

## 3. 데이터 모델 — 가변 크기 경작지

### Building 확장

```ts
interface Building {
  // ...기존...
  w?: number; // 경작지 전용: 가로 칸 수 (기본 1)
  h?: number; // 경작지 전용: 세로 칸 수 (기본 1)
  sownArea?: number; // 경작지 전용: 이번 작기에 파종을 마친 칸 수 (0 ~ w*h)
}
```

- `buildingFootprintTiles`를 **건물 인스턴스(또는 w/h 인자)** 를 받는 형태로 확장하고,
  기존 타입 기반 호출부를 전수 교체한다. field/paddy 외 건물은 기존 타입 크기 그대로.
- 직사각형 허용(3×2, 1×3 등), 각 변 최대 3. 건설비는 **칸수 비례**(`cost × area`).
- 배치 검증은 **모든 칸**이 해당 placement 조건(field 지형 / `isPaddyEligibleTile`)을
  통과해야 한다. 비옥지 보너스는 발자국 내 비옥 칸 비율로 계산한다.
- 저장 스키마 **v22 (가산적)**: 구버전 밭·논은 `w=h=1, sownArea=fieldGrowth>0?1:0`으로
  로드. 기존 1×1 밭을 합치는 도구는 만들지 않는다 — 철거 후 재배치가 경로다.

### 작기(作期) 모델 — 파종 → 생육 → 수확

지금은 `fieldGrowth` 하나가 파종과 생육을 겸한다. 면적이 생기면 "**몇 칸을 심었는가**"와
"**심은 것이 얼마나 자랐는가**"를 분리해야 인력 부족의 손실이 읽힌다:

| 단계 | 철 | 노동 | 상태 변화 |
|---|---|---|---|
| 파종 | `plantSeasons` | 농부 작업량 → `sownArea` 증가 (칸당 파종 노동량은 CONFIG) | 파종철이 끝나면 `sownArea` 확정 — **못 심은 칸은 그해 놀린다** |
| 생육 | `growSeasons` | 농부 작업량 → `fieldGrowth` 증가 (심은 면적이 넓을수록 같은 인력으로 더디게 오른다: 작업량 ÷ `sownArea`) | 0~100, 날씨 배수 기존 유지 |
| 수확 | `harvestSeasons` | 농부 작업량 → `fieldGrowth` 차감, 산출 = 차감분 × 칸당 소출 × `sownArea` × 비옥 비율 | 겨울 진입 시 잔여분 **기존 서리 동결 규칙**으로 소멸 |

- **소출 총량 = 작물 yield × sownArea** (1×1 대비 칸수만큼 정직하게 늘어난다).
- **필요 인원**: `WORKER_SLOT_CONFIG`의 고정 슬롯을 경작지에 한해 동적으로 —
  시작값 제안 **`ceil(area / 3)`** (1×1~3칸=1명, 4~6칸=2명, 9칸=3명). 이것이 "이 인원이면
  제철 안에 파종·수확을 마친다"의 기준이고, 슬롯 수 자체는 이 값으로 노출한다.
  노동 계수는 **필요 인원을 채웠을 때 3×3이 딱 맞게 돌아가도록** 역산해 CONFIG에 둔다.
- **인력 부족의 손실은 두 군데서 자연 발생한다** (별도 페널티 수치 불필요):
  1. 봄 파종 미완 → `sownArea < area` → 그만큼 소출 상한이 깎인다.
  2. 가을 수확 미완 → `fieldGrowth` 잔여 → 겨울 서리 동결(기존 규칙)로 소멸.
- UI: 경작지 선택 패널에 `파종 6/9칸 · 성장 72% · 농부 2/3` 식으로 단계와 인력 충족을
  상시 표기한다. 내역 없는 손실은 버그로 오해받는다(만족도 계획의 교훈 그대로).

## 4. 드래그 배치 UI

- `placingType`이 field/paddy일 때: GameCanvas에서 **pointerdown이 기준 칸을 고정**하고
  드래그로 사각형을 늘린다(각 변 3으로 클램프). pointerup에 전체 칸 유효 + 비용 충족이면
  배치. 드래그 없이 클릭만 하면 기존처럼 1×1 — 기존 조작감을 깨지 않는다.
- 프리뷰: 칸별 초록/빨강 오버레이 + `3×2 · 목재 12 · 농부 2명` 요약 툴팁.
- 화면 이동 드래그와의 충돌: 배치 모드 중에는 좌클릭 드래그를 크기 지정에 양보하고,
  화면 이동은 중클릭/우클릭 드래그 또는 가장자리 스크롤로 우회(기존 DRAG_THRESHOLD 로직
  분기).
- 렌더러: 경작지 스프라이트를 발자국 전 칸에 타일링하고, 성장 단계 표현은 건물 단위로
  통일(칸별 개별 성장 없음 — §7-1). 선택 하이라이트·철거는 발자국 전체가 한 덩어리.

## 5. 농우(農牛) — 소를 밭에 내주기

- **전역 패시브(현행 +8%/축사, 최대 +24%)를 명시적 배정으로 대체한다.**
  결정 없는 보너스를 결정 있는 보너스로 바꾸는 것이 목적이다.
- **배정 모델**: 소를 기르는 축사의 소 마릿수가 **농우 풀**이 된다. 경작지 선택 패널에
  `농우 사용` 토글(또는 마릿수 스피너) — 배정 시 풀에서 차감, 겨울·휴경 시 자동 반납.
  경작지당 최대 1마리(3×3은 2마리까지 — CONFIG).
- **효과**: 농우가 배정된 경작지는 파종·생육·수확 작업량 **×1.4** (시작값, CONFIG).
  "소 한 마리가 장정 몇 사람 몫"이라는 우경의 결을 그대로 — 필요 인원을 한 명 덜
  쓰고도 제철을 맞추는 수단이 된다.
- **비용/긴장**: 농우로 나간 소도 축사 사료(건초) 소비는 그대로다. 도축·번식 계산에서
  농우 배정 마릿수를 어떻게 다룰지는 §7-3. 소가 죽거나 도축되어 풀이 줄면 배정이
  초과된 경작지부터 자동 해제하고 로그를 남긴다.
- 저장: 경작지에 `plowOxen?: number` (v22에 포함), 로드 시 풀 초과분 자동 보정.

  버려지고 "씨를 넣지 못한 채 놀게 됩니다" 로그(simulation.ts settleSowingDeadline).
  겨울 서리 동결과 조상(早霜) 사건이 `sownArea`도 함께 리셋. **1×1 노동 효율도 3배가
  된다(의도된 생산 효율 상향)** — 관련 테스트 기대값 갱신.
- **파종 시한 밸런스 확정 (사용자 지시: 혼자 3×3 커버는 불가여야 한다).**
  `sowWorkPerTile` 6 → **18**. 실측(테스트 시뮬레이션, 봄 한 철): 농부 1명이 3×3에
  붙으면 **4.9/9칸**에서 봄이 끝나 4칸을 놀리고, 적정 인원 3명이면 7일째쯤 9칸을 다 심고
  봄 말 성장 47%에 도달한다. 이 경계는 `test_farm_plot_sizing.mjs`의 밸런스 블록이
  상시 검증한다(혼자 = 3~7칸, 3명 = 9칸 완파종). 실제 게임에서는 식사·운반 이동이 겹쳐
  혼자인 쪽이 더 불리해진다(의도 방향).
- **농우** (livestock.ts): 소 축사 마릿수 = 풀(`plowOxenPool`), 경작지 선택 패널에서
  0~상한 마릿수 배정(`setPlotPlowOxen`, 기본 상한 1, 7칸 이상 +1). 배수는 마리당
  +40%(`plotWorkMultiplier`). 도축·약탈·아사·축종 변경 시 `reconcilePlowOxen`이 초과
  배정을 자동 해제(늦게 지은 경작지부터). **전역 패시브(축사당 +8%)는 제거.**
- **드래그 배치** (GameCanvas): 경작지 배치 중 좌클릭 드래그가 크기 지정(변당 3 클램프,

  타일링하고 **파종을 마친 칸(floor(sownArea))까지만 작물을 그린다** — 못 심은 칸은
  맨땅(§7-1 확정 그대로). 프리뷰는 칸별 초록/빨강 + `w×h·비용·농부 n명` 툴팁.
- 저장 스키마 **v22**: 로드 정규화에서 `w/h` 클램프, `sownArea`는 구버전이면
  "자라던 밭 = 전체 파종"으로 채움, `plowOxen` 0 기본. `test_farm_plot_sizing.mjs`로
  v21 세이브 로드 검증.
- 브라우저 실검증: 드래그로 2×1 배치(비용 목재 4·도구 2 차감), 무효 칸·자원 부족 거부,

  "2×1 경작지 · 파종 0/2칸 · 성장 0%" 표기 확인.
