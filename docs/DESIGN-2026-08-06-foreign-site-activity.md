# 타 부족 거주지 활동 설계 — 생활대·경제·왕래

> **계획 상태:** 일부 완료
> **상태 갱신:** 2026-08-06 — A0~A3의 실제 생활·순찰 활동대, 3일 경제, 선택·미니맵, 계절별 생활권 확장·축소, 기존 시설 유예와 v64 저장까지 구현했다.

- 작성일: 2026-08-06
- 관련 시스템: `foreignSites`, `foreignSiteActivity`, 생활권, 교역, 외교, 이민·귀순, 습격

## 0. 현행 진단

지도에는 정주 부락·어로 취락·계절 사냥 야영지·변경 마적 산채가 있고, 생활권·교역·예물·항의·산채 토벌도 연결되어 있다. 부락 주변에는 농부·어부·운반꾼이 오가는 모습과 밭·건조대·배 같은 부속물도 보인다.

그러나 현재 보이는 인물은 시간값으로 같은 경로를 반복하는 **장식용 배우**다. 거주지의 `population`, `foodStock`, `tradeStock`, `status`도 일부 외교·이민 결과를 제외하면 생성 당시 값에 머문다. 따라서 플레이어가 보는 것은 살아 움직이는 이웃이 아니라 외교 버튼이 붙은 고정 표식에 가깝다.

이 개편의 핵심은 타 부족을 플레이어 마을과 같은 해상도의 두 번째 정착지로 시뮬레이션하는 것이 아니다. 거주지마다 소수의 **대표 활동대**를 실제 지도 위에 보내고, 그 귀환 결과가 거주지 단위 경제와 상태를 바꾸게 해 적은 비용으로 살아 있는 이웃의 인상을 만드는 것이다.

## 1. 목표

1. 타 부족 사람들이 자기 거주지에서 나와 생활권으로 이동하고 일한 뒤 물자를 들고 돌아오는 모습이 보인다.
2. 사냥·어업·교역·순찰·계절 이동의 결과가 거주지 식량·교역 재고·상태에 반영된다.
3. 생활권 침범 경고, 교역 방문, 원조 요청, 습격 출발이 가능하면 지도 위 실제 왕래에서 파생된다.
4. 관계가 좋아지거나 나빠지면 같은 거주지도 활동과 태도가 달라져 외교가 지도 풍경에 드러난다.
5. 번영·인구·자원 이용이 이어지면 생활권이 천천히 넓어지고, 위기·고갈이 이어지면 바깥부터 줄어든다.
6. 저장·불러오기와 대형 지도에서도 결정적이고 가벼워야 한다.

## 2. 핵심 결정

### 2-1. 전체 주민 대신 대표 활동대

- 거주지마다 동시에 **생활 활동대 1개 + 외교·군사 활동대 1개**, 최대 2개만 둔다.
- 활동대 하나는 화면상 1~4명의 배우로 보이지만 상태에서는 한 개체로 저장한다.
- 거주지 안의 기존 장식용 주민은 일상 분위기를 위해 유지한다. 거주지 밖으로 나가는 배우만 실제 `ForeignSiteParty`가 맡는다.
- 대표 활동대가 길을 못 찾았다고 거주지 전체가 즉시 굶지는 않는다. 최소 생계는 추상 생산으로 남기고, 실제 귀환은 잉여·교역품·상태 개선분을 만든다.

### 2-2. 실제 지도 이동과 낮은 빈도의 경제

- 활동대 이동은 서브틱에 맞춰 부드럽게 보이되 경로는 출발·목표 무효화 때만 계산한다.
- 거주지 경제 결산은 매일이 아니라 기본 **3일 간격**으로 처리한다. 활동대 귀환은 즉시 장부에 쌓고 다음 결산에서 소비·상태와 함께 확정한다.
- 난수는 `seed + siteId + activitySequence + departureDay`에서 결정해 저장 왕복과 재실행 결과를 고정한다.
- 지도에 보이는 이동과 경제 결과가 어긋나지 않도록 생산품은 목표 지점 도착이 아니라 **거주지 귀환 시점**에 입고한다.

### 2-3. 공유 자원은 제한적으로 실제 경쟁

- 사냥대는 자기 사냥 생활권 안의 실제 짐승 서식지 비축을, 어로대는 자기 어로 생활권 안의 실제 어장·갯벌 비축을 소량 사용한다.
- 한 활동대가 한 번에 가져갈 수 있는 양과 하루 비축 감소율에 상한을 둬 플레이어가 모르는 사이 자원이 바닥나는 일을 막는다.
- 농경은 외부 거주지의 절차형 밭 부속물에서 추상 생산한다. 플레이어의 밭을 수확하거나 새 밭을 점유하지 않는다.
- 벌목은 첫 범위에서 실제 나무를 없애지 않는다. 숲길 채집은 약초·땔감의 추상 생산만 하며, 지형 변경은 별도 확장으로 남긴다.

### 2-4. 외교는 활동을 바꾸되 생존을 잠그지 않음

- 우호 관계에서는 상단·사절·선물 전달이 늘고, 통행 협정이 있으면 플레이어 장터까지 실제로 찾아올 수 있다.
- 경계심이 높으면 생활 활동대 대신 순찰대가 더 자주 나오며, 무단 침범을 발견하면 현장 경고가 먼저 발생한다.
- 적대 관계라도 민간 활동대를 임의 공격하는 기능은 첫 범위에 넣지 않는다. 공격·나포·점령은 전쟁 체계가 필요하므로 별도 계획으로 분리한다.

### 2-5. 생활권은 한 계절에 한 칸씩 움직임

- 생활권 변화는 현재 원형 `ClaimZone` 계약을 유지해 **반경 1칸 단위**로 처리한다. 첫 구현에서 자유 형태 영토 폴리곤은 만들지 않는다.
- 확장·축소 평가는 계절마다 한 번만 하며, 같은 구역은 한 계절에 최대 1칸만 변한다.
- 번영·인구·최근 활동 성공·충분한 주변 자원이 확장 압력을 만들고, 굶주림·질병·인구 감소·서식지나 어장 고갈은 축소 압력을 만든다.
- 숫자만 즉시 바꾸지 않는다. 확장 예정 외곽을 순찰대가 돌아 표식을 세우고 귀환하면 경계가 확정된다. 축소는 바깥 활동 목표가 사라지고 경계 표시가 한 계절 동안 흐려진 뒤 확정된다.
- 새 경계가 기존 플레이어 시설을 덮더라도 즉시 무단 점유 벌칙을 주지 않는다. 기존 시설에는 한 계절의 **기존 이용 유예**를 주고, 그동안 철수하거나 기존 생활권 협정을 제안할 수 있게 한다.
- 플레이어 중심지와 초기 정착 핵심권, 다른 외부 거주지 발자국, 물리적으로 맞지 않는 지형은 확장 후보에서 제외한다.
- 유효한 생활권 협정이 있는 구역은 계약 기간 중 실제 반경을 축소하지 않는다. 축소 압력은 `targetRadius`에 쌓아 두었다가 협정 만료·갱신 때 반영해 이미 지불한 권리가 갑자기 사라지지 않게 한다.
- 첫 범위에서는 서로 다른 타 부족 생활권끼리 겹치지 않게 한다. 부족 간 영토 분쟁은 후반 통일 세력·부족 전쟁 계획으로 남긴다.

## 3. 거주지별 활동

| 거주지 | 평시 생활 활동 | 외교·군사 활동 | 계절·상태 변화 |
|---|---|---|---|
| 정주 부락 | 경작, 숲 채집, 짐 운반 | 생활권 순찰, 육로 상단, 전령 | 가을 곡물 증가, 겨울 외부 활동 감소 |
| 어로 취락 | 연안 낚시, 어장 조업, 건조대 운반 | 수산물 상단, 물길·연안 순찰 | 결빙 수역 출어 중지, 바다는 풍랑일 출어 취소 |
| 계절 사냥 야영지 | 사냥, 가죽·고기 운반 | 사냥권 순찰, 계절 전령 | 활성 계절 초 입장 행렬, 끝에는 짐을 싣고 지도 밖으로 퇴장 |
| 변경 마적 산채 | 식량 조달, 산길 정찰 | 초계, 습격대 출발, 패잔병 귀환 | 경계심이 높을수록 초계 증가, 토벌·패배 상태 반영 |
| 전초기지(`outpost`) | 보급 운반 | 순찰·전령 | 후속 콘텐츠가 이 유형을 만들 때 같은 틀 재사용 |
| 폐허 | 없음 | 없음 | 흔적·전리품 조사만 후속 범위 |

### 활동대 종류

```ts
type ForeignSitePartyKind =
  | 'farm' | 'hunt' | 'fish' | 'forage'
  | 'haul' | 'patrol' | 'caravan' | 'messenger'
  | 'seasonalMigration' | 'lairScout';
```

- `farm`: 부락과 절차형 밭 사이를 오가며 곡물 장부를 만든다.
- `hunt`: 생활권 안 서식지를 찾아 고기·가죽을 얻는다.
- `fish`: 물가 또는 어장을 찾아 물고기를 얻는다. 깊은 수역은 외부 어선 표현이 준비된 경우에만 사용한다.
- `forage`: 숲 생활권에서 약초·소량 땔감을 얻되 나무 타일은 바꾸지 않는다.
- `haul`: 생산 지점에서 거주지·건조대·창고로 물자를 옮겨 활동 결과를 눈에 보이게 한다.
- `patrol`: 생활권 경계를 돌며 무단 작업과 건설을 발견한다.
- `caravan`: 거주지 재고를 싣고 지도 가장자리 또는 협정된 플레이어 장터로 이동한다.
- `messenger`: 원조 요청·경고·예물 답신처럼 모달의 발신자를 실제 이동으로 표현한다.
- `seasonalMigration`: 야영지의 입장·퇴장을 실제 상태로 만든다.
- `lairScout`: 산채 주변 초계와 습격 전 정찰을 표현한다. 실제 습격은 기존 `RaiderBand`를 계속 쓴다.

## 4. 상태 계약

### 4-1. 활동대

```ts
interface ForeignSiteParty {
  id: number;
  siteId: number;
  kind: ForeignSitePartyKind;
  phase: 'outbound' | 'working' | 'returning' | 'waiting' | 'retreating';
  x: number; y: number;
  px: number; py: number;
  path: Array<{ x: number; y: number }>;
  target: { x: number; y: number } | null;
  memberCount: number;
  cargo: Partial<Record<ResourceId, number>>;
  departedDay: number;
  workUntilTick?: number;
  activitySequence: number;
  spotted: boolean;
}
```

`GameState`에는 `foreignSiteParties`, `nextForeignSitePartyId`를 둔다. `ForeignSite`에는 최소한 다음 결산 정보만 추가한다.

```ts
interface ForeignSiteActivityLedger {
  lastSettlementDay: number;
  nextActivityDay: number;
  activitySequence: number;
  condition: 'stable' | 'prosperous' | 'hungry' | 'sick';
  surplusSettlements: number;
  hungerDays: number;
  sicknessDays: number;
  pendingProduction: Partial<Record<ResourceId, number>>;
  recentProduction: Partial<Record<ResourceId, number>>;
}
```

`ClaimZone`에는 현재 경계와 장기 압력을 분리하는 정보를 추가한다.

```ts
interface ClaimZoneGrowthState {
  baseRadius: number;
  targetRadius: number;
  pressure: number;
  lastBoundaryChangeDay: number;
  pendingChange?: 'expand' | 'contract';
  previousRadius?: number;
  establishedUseGraceUntilDay?: number;
  establishedUseBuildingIds: number[];
}
```

- 생활 활동대는 v63, 생활권 성장·유예 장부는 v64 저장 스키마에 반영한다.
- 구 저장은 활동대가 없는 상태로 정규화하고 각 거주지의 다음 출발일을 `siteId`로 분산해 한날 동시에 쏟아져 나오지 않게 한다.
- 부모 거주지가 불타거나 버려지면 귀환 중 활동대는 지도 가장자리로 퇴각하고 나머지는 제거한다.
- 구 저장의 생활권은 현재 `radius`를 `baseRadius`와 `targetRadius`의 시작값으로 삼아 불러오자마자 경계가 움직이지 않게 한다.

### 4-2. 경로와 통행

- 주민용 생활권 금지 판정이나 침입자용 숲·돌파 비용을 그대로 쓰지 않고 외부 활동대용 얇은 통행 규칙을 둔다.
- 산지·노두·바다 등 물리적 불통 지형과 완공 건물 충돌은 지킨다. 다리·나루·열린 통행 협정은 사용할 수 있다.
- 생활 활동은 원칙적으로 자기 생활권 안에서만 목표를 고른다. 플레이어 건물 발자국과 공사터는 목표에서 제외한다.
- 플레이어 성벽을 임의로 통과하지 않는다. 장터 방문 상단은 도달 가능한 장터 외곽까지만 가며, 길이 없으면 기존 지도 밖 교역으로 폴백한다.
- 경로가 막히면 매 틱 재탐색하지 않고 목표를 한 번 바꾼 뒤, 그래도 실패하면 귀환 또는 출발 취소한다.

## 5. 거주지 경제와 상태 변화

### 5-1. 3일 결산

1. 활동대가 귀환하며 쌓은 생산품을 `foodStock`·`tradeStock`에 입고한다.
2. 인구에 비례한 추상 식량을 소비한다.
3. 계절·날씨·거주지 종류에 따른 최소 생계 생산을 더한다.
4. 식량 일분, 질병 누적, 잉여 재고를 기준으로 상태를 갱신한다.
5. 상태가 바뀐 경우에만 거주지 기억과 중요 로그를 남긴다.

### 5-2. 상태 전이

- `stable → prosperous`: 두 번 이상의 결산 동안 충분한 식량 일분과 교역 잉여를 유지한다.
- `stable/prosperous → hungry`: 식량이 경고선 아래로 내려간 상태가 두 번의 결산 동안 지속된다.
- `hungry → stable`: 식량을 채운 뒤 한 번 더 결산할 때까지 회복을 유예해 상태가 매번 뒤집히지 않게 한다.
- `sick`: 굶주림·혹한·전염 압박으로 별도 누적되며 약초와 식량이 있으면 완화한다.
- `abandoned`: 인구 0 또는 최소 한 계절 이상 지속된 심각한 위기 뒤에만 가능하다. 짧은 흉년 한 번으로 거주지가 사라지지 않는다.
- 생계 상태는 장부의 `condition`에 저장한다. 평화로운 거주지는 기존 `site.status`에도 이를 반영하되, `hostile`, `fortified`, `abandoned`, `burned` 같은 운영·군사 상태는 경제 결산이 덮어쓰지 않는다.

### 5-3. 교역 재고

- 실제 거주지에서 출발한 상단은 `sourceSiteId`를 갖고 해당 `tradeStock`을 한도로 사용한다.
- 플레이어가 건넨 물자는 원천 거주지 재고에 들어가 다음 결산의 식량·생산·요청 판단에 영향을 준다.
- 지도에 대응 거주지가 없는 세력의 기존 추상 교역은 유지한다.
- 정기거래·플레이어 요청 교역을 한 번에 전부 실체화하지 않는다. 첫 단계에서는 거주지 발 상단만 실제 이동시키고 나머지는 현행 왕복일을 유지한다.

## 6. 지도에서 보이는 상호작용

### 6-1. 발견과 선택

- 부모 거주지를 발견했으면 그 소속 활동대는 지도와 미니맵에 표시한다.
- 미발견 거주지의 활동대는 주민·파수꾼·망루 일정 거리 안에 들어오면 그 이동 동안만 `spotted`가 된다. 이때는 “소속 모를 사냥꾼/상단”으로 보이고 거주지 위치를 자동 공개하지 않는다.
- 활동대를 클릭하면 주민과 같은 하단 원형 선택 표시를 쓰되 명령은 내릴 수 없다.
- 정보에는 소속, 목적, 인원, 화물의 대략값, 출발지·귀환 상태, 현재 태도를 표시한다. 정보 정확도는 거주지 발견 여부와 관계에 따라 차등한다.

### 6-2. 생활권 순찰

- 순찰대가 무단 건설·작업 현장에 도달하면 기존 생활권 항의의 첫 경고를 현장 사건으로 바꾼다.
- 순찰대가 없거나 길이 막힌 경우에도 현재의 일일 긴장 누적은 안전망으로 유지한다. 시각화 실패가 외교 규칙 무효화로 이어지지 않는다.
- 협정된 생활권에서는 순찰대가 플레이어 주민을 막지 않고 우호 인사 또는 약조 확인 기억만 남긴다.

### 6-3. 생활권 확장과 축소

1. 계절 결산에서 구역별 `pressure`를 평가한다.
   - 확장 가산: `prosperous`, 인구 증가, 최근 사냥·어업·경작 귀환 성공, 충분한 대상 자원, 높은 군사력의 통행 순찰.
   - 축소 가산: `hungry`·`sick`, 인구 감소, 연속 활동 실패, 서식지·어장 고갈, 거주지 비활성.
2. 임계값을 넘으면 `targetRadius`를 현재 반경보다 1칸 늘리거나 줄이고 `pendingChange`를 만든다.
3. 확장은 순찰대가 새 외곽의 유효 지점 2~4곳을 방문한 뒤 확정한다. 길이 없거나 금지 대상과 충돌하면 취소하고 압력 일부만 남긴다.
4. 축소는 즉시 외교 판정을 바꾸지 않고 한 계절의 예고 상태를 거친다. 바깥 고리의 경계선과 활동이 흐려지고 다음 계절 결산에 확정된다.
5. 경계 변화는 발견된 구역에만 중요 로그와 거주지 기억을 남긴다. 미발견 구역은 조용히 변하고 나중에 발견한 현재 경계만 보여 준다.

- 확장된 고리에 이미 있던 플레이어 건물 ID를 `establishedUseBuildingIds`에 스냅샷하고, 그 시설만 `establishedUseGraceUntilDay`까지 긴장 누적에서 제외한다. 유예 중 새 건설·새 작업은 보호하지 않는다.
- 유예가 끝날 때 플레이어 시설이 남아 있으면 순찰대가 최종 경고를 전달한 뒤 현행 생활권 긴장 규칙으로 넘어간다.
- 생활권 협정을 맺으면 확장된 고리도 같은 `zone.id`의 권리에 포함한다. 단, 협정 체결 직후 관계를 악용해 강제로 확장시키는 직접 명령은 없다.
- 구역 종류별 반경 상·하한을 설정으로 둔다. 초기안은 최소 2칸, 생성 반경보다 최대 2칸까지만 확장해 지도 대부분이 장기간 자동 점유되는 일을 막는다.

### 6-4. 위기와 요청

- `hungry`·`sick` 상태가 지속되고 관계가 나쁘지 않으면 전령이 중심지 또는 장터로 와 곡물·약초 원조를 청할 수 있다.
- 요청은 같은 거주지에서 한 계절에 한 번을 넘지 않으며, 전령 도착 전에는 모달을 열지 않는다.
- 원조는 식량·질병 장부를 직접 개선하고 호의·신용·관계·은혜를 올린다. 거절은 즉시 적대로 만들지 않되 기억에 남긴다.

### 6-5. 습격과 산채

- 변경 마적 습격은 지금처럼 산채에서 출발한다. 산채의 조달·초계 활동은 경계심과 군사력 정보의 시각적 근거가 된다.
- 지도에 해당 세력의 운용 가능한 거주지가 있으면 그 세력의 습격도 거주지 주변에서 출발할 수 있다. 거주지가 없거나 길이 없으면 기존 지도 가장자리 출발로 폴백한다.
- 생활 활동대와 습격대를 같은 개체로 바꾸지 않는다. 습격 발생 시 해당 거주지의 군사 활동 슬롯을 잠그고 기존 `RaiderBand`를 생성한다.
- 화친 맹약·습격 자격·관계 조건은 현행 외교 규칙을 그대로 우선한다.

## 7. 연출과 UI

- 기존 농부·어부·사냥꾼·운반꾼 표준/HD 스프라이트와 짐 운반 상태를 재사용한다.
- 민간 활동대를 북방 습격자 스프라이트로 그리지 않는다. 첫 구현은 직업 실루엣과 세력색 작은 표식으로 구분하고, 별도 민간 복식 자산은 후속 아트 범위다.
- 실제 활동대는 타일 단위 순간이동이 아니라 `px/py` 보간으로 부드럽게 이동한다.
- 거주지 패널에 다음을 추가한다.
  - 현재 상태의 원인과 대략적인 식량 일분
  - 현재 밖에 나간 활동대와 “위치 보기”
  - 최근 생산·소비 요약
  - 생활권별 현재 반경, 확장·축소 압력, 다음 계절 검토와 기존 이용 유예
  - 다음 활동 예상 시기 또는 날씨로 인한 중단 사유
- 일상적인 출발·귀환은 로그를 남기지 않는다. 최초 목격, 상태 변화, 상단 도착, 현장 경고, 원조 요청, 계절 이동처럼 판단이 필요한 일만 기록한다.
- 활동대 경로는 상시 선으로 그리지 않는다. 선택했을 때 목적지 표식과 짧은 점선만 표시한다.

## 10. 성능·안전 장치

- 기본 생성 거주지 수 기준 활동대 최대 8개, 대형 지도에서도 거주지당 상한은 변하지 않는다.
- 경로 탐색은 출발·목표 변경·다음 칸 무효화 때만 수행한다.
- 활동 목표 후보는 전체 지도 검색 대신 해당 거주지 생활권과 미리 계산한 부속물에서 고른다.
- 거주지 결산은 3일 간격으로 분산하고 `siteId` 오프셋을 둔다.
- 생활권 확장 후보는 계절 결산 때 새 외곽 고리만 검사하며 매일 전체 지도를 다시 훑지 않는다.
- 활동대가 플레이어 주민을 밀거나 길을 예약하지 않는다. 같은 칸 겹침은 허용한다.
- 공성·전술전·대형 재해 중에는 새 외교 활동대 출발을 막고, 이미 나온 생활 활동대는 귀환 또는 대기한다.
- 튜토리얼에서는 무작위 위기·요청·적대 전환을 잠그되 일상 생활 활동은 보여 줄 수 있다.

## 11. 비범위와 후속

- 타 부족 전체 주민의 이름·가족·주거·욕구 시뮬레이션
- 플레이어가 외부 거주지에 건물을 짓거나 직접 작업자를 배정하는 기능
- 기존 생활권 반경 상한을 넘는 영토 확장, 새 구역 창설, 새 건물 영구 건설, 지도 지형 벌목
- 민간 활동대 자유 공격·포로·약탈·점령
- 타 부족끼리의 정복전과 후반 통일 세력 아크
- 활동대끼리의 전술 전투

이 항목들은 본 계획의 상태·활동대 계약 위에 올릴 수 있지만, 첫 구현에 포함하면 외교·전쟁·지도 점유를 동시에 다시 설계해야 하므로 분리한다.

## 12. 검증 계약

### 결정적 표적 테스트

- 같은 seed·날짜·거주지에서 활동 종류·목표·수확량이 같다.
- 출발·작업·귀환 중 저장 왕복 뒤 경로·화물·입고가 한 번만 이어진다.
- 사냥·어획은 자기 생활권 안의 비축만 사용하고 0 아래로 내리지 않는다.
- 결빙 호수·풍랑·눈보라·비활성 계절에는 해당 활동이 출발하지 않는다.
- 식량 상태 전이는 유예와 회복 걸쇠를 지켜 매 결산마다 흔들리지 않는다.
- 생활권은 같은 계절에 두 번 변하지 않고 반경 상·하한과 금지 완충권을 지킨다.
- 확장 이전 플레이어 시설은 한 계절 동안 긴장 누적에서 제외되고, 유예 중 새 작업은 제외되지 않는다.
- 유효한 생활권 협정은 만료 전 축소되지 않으며 저장 왕복 뒤 대기 중 `targetRadius`가 유지된다.
- 생활권 순찰 경고와 기존 일일 긴장 안전망이 같은 침범을 이중 처벌하지 않는다.
- 현지 상단 거래는 원천 거주지 재고와 플레이어 재고를 한 번씩만 바꾼다.
- 타 세력 습격은 운용 가능한 거주지에서 출발하고, 없으면 지도 가장자리 폴백을 유지한다.
- 구 저장은 빈 활동대와 분산된 다음 출발일로 정상화된다.

### 통합·실화면 검증

- `test_foreign_sites`, 외교 E2~E6, 교역, 이민·귀순, 습격·공성, 저장 회귀를 통과한다.
