# 착용 장비(옷·신발) 개인화와 가죽 경제 — 설계

> **계획 상태:** 완료
> **상태 갱신:** 2026-07-29 — 착용·마모·제작·저장·슬롯 UI를 구현했고 사망 시 회수 없음으로 확정했다.

- 작성일: 2026-07-28
- 발단: 가죽공방이 초반 위기만 넘기면 개점휴업 상태가 되는 문제
- 범위: 옷·신발을 **주민 개인 착용물**로 전환 + 신발 도입 + 가죽공방 다품목화

## 1. 문제 진단

가죽이 남아도는 게 아니라, **가죽의 최종재가 저량(stock) 수요뿐**이다.

| 항목 | 현재 값 | 출처 |
|---|---|---|
| 계절 길이 | 12일 (1년 48일) | `CONFIG.time.seasonDays` |
| 옷 마모 | `인구가중치 × 0.02`/일, **겨울에만** | `simulation.ts` 겨울 분기 |
| 옷 보급 목표 | `옷×clothingValue / 인구 ≥ 1` | `clothingCoverageTotal` |
| 가죽공방 산출 | 무두장이 1인당 가죽 2 → 가죽옷 1/일 | `CONFIG.production.tanneryHidePerDay` |

인구 20 기준:

- 목표 재고 ≈ 가죽옷 18벌 → 무두장이 2명이면 **9일이면 충족**
- 이후 연간 수요 `20 × 0.02 × 12일 = 4.8벌` vs 연간 공급 능력 `96벌` → **20배 과잉**
- 지속적 가죽 수요는 사실상 **세공(연 1회 가죽 8 + 가죽옷 6)** 뿐

기존 가죽 소비처는 전부 일회성이거나 미미하다 — 각궁 0.5/개(진 승격 후), 사냥막 2, 당집 2, 뇌물·조공·선물.

> **결론**: 새 소비처를 만들어도 그것이 또 저량이면 며칠 뒤 같은 상태가 된다.
> 수요를 **유량(flow)** 으로 바꿔야 한다.

## 2. 해법의 방향

옷·신발을 마을 단위 보급률에서 **주민 개인 착용물**로 옮긴다.

**설계 기준선**: 선택이 의미 있으면 플레이어가 지급, 유지 노동이면 주민이 자율 수령.

| 장비 | 배분 방식 | 이유 |
|---|---|---|
| 수레 | **직접 지급** (유지) | 수량이 적고 누구에게 주느냐가 전략적 선택 |
| 전투 장비(무기·군마) | **직접 지급** (유지) | 위와 동일 |
| **옷·신발** | **자율 수령** (신규) | 전원이 상시 필요한 생활 필수품. 20명분 지급은 결정이 아니라 잡무 |

개인화가 주는 것:

1. **부족이 사람으로 보인다.** 지금 보급률 0.6은 "전원이 60%만큼 추운" 뭉개진 상태다. 개인화하면 신발 없는 3명이 특정되고, 그 사람이 느려지고 병에 걸린다.
2. **수요가 자동으로 유량이 된다.** `인원수 × 활동량`으로 매일 닳는다.
3. **기존 에이전트 시뮬레이션의 결과 맞는다.** 이 게임은 이미 운반·하역·출퇴근을 눈에 보이게 굴린다.

## 3. 자료 구조

한 시스템, 두 칸. 나중에 벙거지·장갑을 추가해도 슬롯만 늘리면 된다.

```ts
// types.ts
export type WearableSlot = 'clothing' | 'footwear';

export interface WornItem {
  resource: ResourceId; // hideClothes | cottonClothes | strawShoes | leatherShoes
  wear: number;       // 0 = 새것, 1 이상 = 수명 소진
}

// Resident에 추가
worn?: Partial<Record<WearableSlot, WornItem>>;
```

`worn`이 없거나 슬롯이 비면 **맨몸/맨발**이며, 그것이 페널티의 근거다.

### 새 자원

| id | 이름 | 재료 | 수명 배수 | 생산처 |
|---|---|---|---|---|
| `strawShoes` | 짚신 | 짚(`hay`) 2 | 1.0 | **가내수공업** — 저녁에 집에 있는 주민 (§7-1) |
| `leatherShoes` | 가죽신 | 가죽 1.5 | 3.0 | 가죽공방 (§7-2) |

`hay`는 이미 수확 부산물로 존재하고 지금은 가축 사료 외 용도가 없다 (`hayFromHarvestProgress`).
짚신 재료로 재사용하면 **새 원료 자원 0개**로 시작하면서 "사료냐 신발이냐" 긴장이 덤으로 생긴다.

티어 구조: **맨발 → 짚신(가내수공업) → 가죽신(가죽공방)**.
초반에는 밭만 있으면 짚이 나오므로 건물 없이 맨발을 면하고, 가죽공방이 서면 오래 가는 가죽신으로 올라간다.

## 4. 자율 수령 — 수령 시점이 이 설계의 핵심

매 틱 검사하면 창고 왕복 트래픽이 는다. **하루 1회, 새벽에만** 검사한다.

붙일 자리: `agents.ts`의 `dawnAgentTick` 시작부.
아이도 성인 출근 분기 전에 검사해야 하므로 `morningPreparationAgentTick` 안쪽이 아니라
질병·연령에 따른 조기 반환보다 앞에서 하루 1회 처리한다. 현재 창고 재고가 마을 단위로
추상화되어 있으므로 별도 경로 탐색 없이 재고에서 바로 수령한다.

```
새벽 '아침 채비':
  슬롯이 비었거나 wear >= 1 인가?
    → 창고(isStorageBuilding)에 재고가 있으면 집으러 감 → 착용 → 출근
    → 재고가 없으면 그대로 맨발/맨몸으로 출근 (페널티)
  아니면 → 기존 동작 그대로
```

### 착용 우선순위

창고에 여러 등급이 있으면 **좋은 것부터**. 가죽신이 떨어지면 자동으로 짚신을 신는다.
등급 우선순위는 `WEARABLE_TIERS` 표 하나로 정의하고, 나중에 절목(edict)으로
"가죽신은 파수꾼·사냥꾼 우선" 같은 배급 규칙을 얹을 자리를 남긴다.

### 예외 규칙

| 대상 | 규칙 |
|---|---|
| 아이(`stage`) | 마모 반몫, 수령은 동일 |
| 환자·격리 | 수령하지 않음 (새벽에 안 나감), 마모 없음 |
| 원정·전투 중 | 창고 접근 불가, 마모는 계속 (돌아와서 갈아 신음) |
| 신규 이주민 | 맨발로 도착 — 초반 압박 요소로 활용 |
| 사망·이탈 | **회수하지 않고 소멸**. 착용 중 마모도를 공용 재고의 소수량으로 되돌리는 복잡성을 만들지 않는다 |

## 5. 마모와 효과

### 마모

```
일일 마모 = 기본계수 / 수명배수
          × (야외 노동 가중)      // 걷는 직업일수록 신발이 빨리 닳는다
          × (계절·날씨 가중)      // 겨울·궂은 날에 옷이 빨리 닳는다
          × (아이면 0.5)
```

- **신발**: 운반꾼·사냥꾼·벌목꾼·채광꾼처럼 걷는 직업이 빨리 닳는다 → 사계절 상시 수요
- **옷**: 겨울·혹한에 빨리 닳는다 → 기존 성격 유지하되 사계절 소량 마모

### 효과

| 슬롯 | 효과 | 연결 지점 |
|---|---|---|
| 신발 | 이동속도 배율 | `moveSteps()` — `haulingMoveSpeedMultiplier` 옆에 한 줄 |
| 신발 | 겨울 체온 손실 완화 | `updateResidentNeeds`의 `loss` 계산 |
| 옷 | 겨울 체온 손실 완화 (기존) | 동일 |

맨발이면 이동속도 페널티 + 겨울 동상 위험. 짚신은 이동속도만 회복하고 방한은 약하다.

## 6. 기존 밸런스를 지키는 한 줄

사기(`clothingGood`/`clothingBad`)·승격 조건과 운반 긴급도는 실제 착용 보급을 본다.
자원 HUD는 창고에 남은 재고를 보여야 하므로 별도로 계산한다.

- `agents.ts:1704` — 옷 부족 판정
- `simulation.ts:1383` — 체온 계산의 `clothesCoverage`
- `ui/resourceDisplay.ts:122` — HUD '의복' 그룹 합계

`clothingCoverageTotal`은 "옷을 갖춰 입은 주민의 보온 합계"로 재정의한다.
체온은 전 주민에게 같은 비율을 주지 않고 `residentColdProtection`으로 개인별 계산한다.
HUD의 의복·신발 그룹 합계는 착용 수가 아니라 창고 재고 합계를 유지한다.

신발용으로 `footwearCoverageTotal`을 같은 모양으로 추가하고, HUD에 '신발' 그룹을 하나 더 연다.

## 7. 생산

### 7-1. 짚신 — 가내수공업 (저녁, 집)

짚신은 원래 가내수공업이다. 별도 건물도 직업도 없이 **저녁에 집에 들어간 주민이 자율적으로 삼는다.**

저녁 대역 구조가 이미 이걸 받쳐 준다:

- `leisureAssignments`가 저녁마다 **일부만** 마실 목적지에 배정한다
  (목적지당 `LEISURE_CLUSTER_CAPACITY = 4`명)
- 배정을 못 받은 주민은 `eveningLeisureAgentTick` → `returnHomeAgentTick`으로 **집에 들어간다**
- 순번은 `leisureOrderKey(id, day)`로 매일 돌아간다 → **누가 집에 있느냐가 날마다 바뀐다**

그러니 훅은 한 곳이다 — `returnHomeAgentTick`으로 빠지는 저녁 주민.

```
저녁, 마실 배정 없이 집에 들어간 주민:
  집이 있고 · 아프지 않고 · 창고에 짚이 있고 · 신발 재고가 상한 미만이면
    → phase 'sleeping' 대신 '짚신 삼는 중'
    → 저녁 대역 동안 소량 생산, 밤 대역에 취침으로 전환
  아니면 → 기존대로 취침
```

| 항목 | 값 | 근거 |
|---|---|---|
| 생산량 | 저녁 1회당 0.3켤레 (3일에 1켤레) | 마실 나간 사람은 못 만드니 자연스러운 상한 |
| 재료 | 창고 `hay` 2 → 짚신 1 (마을 재고 직접 차감) | `weaverTick`이 `state.resources.cotton`을 쓰는 관례와 동일 |
| 참여자 | 저녁에 집에 있는 성인 + 아이(반몫) | 짚신 삼기는 아이도 거들던 일 |
| 생산 상한 | 미착용 주민 수 + 여유분을 넘으면 쉰다 | 무한 축적 방지 |
| 짚 하한 | 가축 사료 최소분은 남긴다 | "사료냐 신발이냐" 긴장을 유지하되 가축이 굶지는 않게 |

플레이어 조작은 0이다. 나중에 절목(edict)으로 "짚신 삼기 장려/금지"를 얹을 자리만 남긴다.

### 7-2. 가죽신·가죽옷 — 가죽공방 다품목화

대장간이 이미 품목 선택 구조를 갖고 있다 (`SMITHY_PRODUCT_DEFS` + `building.smithyProduct` + 선택 UI).
`tanneryProduct`로 같은 구조를 복제하면 저장·UI·에이전트 틱이 거의 그대로 재사용된다.

| 품목 | 투입 | 성격 | 도입 시점 |
|---|---|---|---|
| 가죽옷 | 가죽 2 | 저량 (기존) | 지금 |
| **가죽신** | 가죽 1.5 | **유량 — 핵심** | 지금 |
| 마구(길마) | 가죽 3 + 목재 1 | 소 쟁기질·운반 효율 | 후속 |
| 엄심갑 | 가죽 4 | 수비병 방어 | 후속 |

생산 모드는 `자동 / 가죽옷 / 가죽신` 세 가지다. 자동은 미착용 주민과 창고 여유분을
비교해 더 부족한 쪽을 고르고, 플레이어는 필요하면 한 품목으로 고정할 수 있다.

## 8. 구현 순서

| 단계 | 내용 | 검증 |
|---|---|---|
| M1 | `WornItem` 타입 + `worn` 필드 + 세이브 v39 마이그레이션 | 구세이브 로드 |
| M2 | 새 자원 2종 등록 (`types.ts` → `resourceCatalog` → `constants` → `tradePresentation` → `resourceDisplay`) | HUD 표시 |
| M3 | 마모 계산 + `clothingCoverageTotal` 재정의 | 기존 밸런스 회귀 |
| M4 | 새벽 자율 수령 (`morningPreparationAgentTick`) | 장기 시뮬 |
| M5 | 효과 연결 (`moveSteps`, 체온) | 맨발 페널티 확인 |
| M6 | 짚신 가내수공업 (저녁 `returnHomeAgentTick` 분기) | 맨발 해소 속도, 짚 소모 |
| M7 | 가죽공방 `tanneryProduct` + 가죽신 | 가죽공방 가동률 |
| M8 | UI — 주민 패널 착용 표시, HUD '신발' 그룹 | 육안 |

M6이 M7보다 앞선다. 짚신이 먼저 돌아야 "맨발 → 짚신"이 초반 경험이 되고,
가죽신은 그 위에 얹는 상위 티어가 된다.

### 세이브 마이그레이션 (v38 → v39)

구세이브는 기존 보급률만큼 주민에게 배분한다.

```
가죽옷·무명옷 재고 → 보급률 계산 → 상위 N명에게 wear=0.5로 배분, 나머지 재고는 창고에 남김
신발은 전원 없음(맨발)에서 시작 — 새 시스템이므로 자연스럽다
```

## 9. 위험 요소

| 위험 | 완화 |
|---|---|
| 창고 왕복으로 인한 경로탐색 부하 | 하루 1회 새벽에만, 집 근처에서 시작 → 추가 이동 거의 0 |
| 기존 옷 밸런스 붕괴 | 개인별 보온과 마을 보급 합계를 분리하고 관련 호출부를 명시적으로 변경 |
| "채워야 할 게이지" 하나 더 늘어나는 피로 | 신발은 자율 수령·자율 생산이라 플레이어 조작 0. HUD 한 줄만 추가 |
| 초반 짚 부족 | 짚은 수확 부산물이라 밭이 있으면 자동 확보. 가축과 경쟁하되 사료 하한을 둔다 |
| 저녁 짚신 생산이 마실(여가)을 잠식 | 마실 배정자는 건드리지 않는다. 집에 들어간 주민만 삼으므로 사기 계산에 영향 없음 |

## 10. 열어 둔 자리

- 절목(edict)으로 착용 배급 규칙 — "가죽신은 야외 직업 우선"
- 벙거지·장갑 등 슬롯 추가
- 세공 품목에 가죽신 추가
- 장터·부두를 통한 상시 판매처 (남는 가죽옷 처분)
