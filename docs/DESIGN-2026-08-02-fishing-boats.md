# 어선과 출어 설계 — 배무이터·포구·어장

> **계획 상태:** 미착수
> **상태 갱신:** 2026-08-03 — 선행 단계인 갯벌 어살터 구현을 완료했고, 어선은 고산출·풍랑 위험의 미착수 상위 해상 단계로 유지한다.

- 작성일: 2026-08-02
- 관련 설계: [새 게임 설정](DESIGN-2026-08-01-new-game-setup.md)(호수·해안 지형), [채집 영역 체제](DESIGN-2026-08-01-gathering-zones.md)(거점·영역·비축 문법 — G1~G3 구현 완료)

## 0. 문제와 방향

현행 어로는 어부가 나루터(보 등급·강변)에 서서 하는 제자리 낚시다(`fisherTick` — 나루터 상호작용 지점에서 계절·가뭄 배율 수확). 호수·바다가 생기면 이걸로는 부족하다 — **물에 배를 몰고 나가야 지형이 의미를 갖는다.**

핵심 제안: 어선 체계는 새 발명이 아니라 **기존 세 문법의 결합**으로 만든다.
1. **장비 수량 문법의 확장** — 현행 수레는 `resources.carts`와 주민의 `cartEquipped`만 있는 소모성
   장비 수량이며 개별 ID·사용 중 상태가 없다. 어선은 이를 그대로 복제하지 않고, 건조 수량 문법만 참고해
   **개별 선체 상태**로 확장한다. 척수가 동시 출어 인원을 제한한다.
2. **채집 영역 문법 (G1~G3)** — 포구는 물 위에 작업영역을 갖는 채집 거점. 어부는 포구에 배정되어야 출어한다 — 방금 확정된 배치 필수화와 일관.
3. **실이동** — 어부가 배를 타고 물 타일을 실제로 항행해 어장까지 가서 조업하고 만선이면 귀항·하역한다. 이 게임의 핵심 정체성("주민이 실제로 이동하고 운반해야 생산이 완료되는 에이전트 물류")에 따라 **추상 출어(원정식 오프스크린)는 채택하지 않는다.**

## 1. 구성 요소

| 요소 | 내용 | 재사용 문법 |
|---|---|---|
| **배무이터(조선소)** | 물가 배치. 목재+도구로 어선을 건조 (초안: 목재 12·도구 1·6일) | 건물·제작 문법 |
| **어선** | `FishingBoatState` 개별 기물. 선체 ID·소속 포구·승선 어부·위치·적재·내구·상태를 저장. 첫 판은 1척=어부 1명 | 수레의 건조 수량 + 별도 선체 상태 |
| **포구(어막)** | 호수·바다용 어로 거점. **물 타일 위 작업영역**(중심 이동·반경 조절) | G1~G3 채집 거점 — 슬롯·영역·지정 하역 |
| **어장(어군)** | 수역에 생성되는 어군 지점. 비축·소모·회복(고갈 시 이동 조업) | G2 서식지 비축 — 수상 판 |
| **수상 통행** | 배에 탄 에이전트만 물 타일 통행 가능 — 별도 통행 도메인 | 기존 A* + 통행 술어 확장 |
| **하역** | 귀항 후 포구에 하역, 운반꾼이 마을로 | 지정 거점 하역 (G3) |

기존 나루터(강 낚시)는 하위 어로로 존치 — 강 < 호수 < 바다 순으로 산출과 위험이 함께 오른다.
해안의 갯벌 어살터는 본 계획의 선박 단계에 앞서는 별도 후속 구현이다. 어부가 도보로 갯벌
비축을 채취해 안전하고 꾸준한 식량을 얻고, 어선은 더 높은 산출·먼 왕복·풍랑 위험으로 차별화한다.
갯벌 단계는 [해안 전이 지형과 갯벌 어로 구현계획](IMPLEMENTATION-2026-08-03-coastal-transition-tidal-flat.md)에서
완료했으며, 본 문서의 F0~F4 범위는 아직 착수하지 않았다.

### 1-1. 명칭과 역할

- `ferry` 나루터: 현행 강 낚시 거점. 제자리 어로, 보(堡) 등급 유지.
- `fishingPort` 포구(어막): 호수·바다 출어 거점. 수상 작업영역·어선 계류·하역 담당.
- `dock` 부두: 현행 대규모 교역 시설. 포구와 합치지 않는다.
- `boatyard` 배무이터: 어선 건조·수리. 포구의 어획 재고나 작업자 슬롯을 대신하지 않는다.

## 2. 출어 루프

포구 배정 어부 → 계류된 빈 어선 확보(없으면 "어선 없음" 대기 사유) → 승선·출항 → 영역 내 어장으로 항행 → 조업(어장 비축 소모, 적재 상한까지) → 귀항·하역 → 하루 사이클에 따라 귀가. 원거리 어장은 채집 영역 체제 G4(숙식 움막)의 수상 판(어막 숙식)을 후일 검토.

- 첫 판은 **1척=어부 1명**으로 고정한다. 2인 승선은 두 주민의 경로·틱·사망·하선을 동기화해야 하므로 후속 선급으로 미룬다.
- 주민의 육상 A*에 `lake/sea`를 통과 가능으로 더하지 않는다. 승선 지점에서 선박 항행 상태로 전환하고,
  선박 전용 수상 통행 술어와 경로를 사용한다.
- 생산 완료는 포구 하역 시점이다. 조업 중 선체 적재는 마을 `resources.fish`가 아니며, 운반꾼이
  포구 재고를 마을로 옮긴 뒤에야 일반 소비·가공이 사용한다.

## 3. 위험과 계절

- **풍랑**: 날씨 연동 — 풍랑 예보 시 출어 불가, 조업 중 풍랑을 만나면 조난 판정(부상·어선 파손·최악은 실종). 갱도 붕괴의 전조·구조 문법을 참고하되 첫 판은 "출어 금지 + 드문 파손"까지만.
- **겨울**: 호수는 결빙 — 출어 불가(후일 얼음낚시 여지). 바다는 조업 가능하되 위험 배율 상승.
- **가뭄·해빙**: 기존 강 낚시 배율 문법을 수역별로 확장.

## 4. 해안 경제와의 연결

바다 어획 → 자염 소금(해안 타입) → 염장 자반·건어 → 교역. [새 게임 설정](DESIGN-2026-08-01-new-game-setup.md) §2-라의 해안 정체성(제염·교역)이 어선으로 완성된다 — 농수 부족을 어물이 메우는 균형.

## 5. 단계 구성

| 단계 | 내용 | 전제 |
|---|---|---|
| F0 | `FishingBoatState`·포구/배무이터 타입·저장 계약·수상 통행 술어 | S4 호수 지형 |
| F1 | 배무이터 건조·포구 계류·1인 승하선 | F0 |
| F2 | 호수 실항행·조업·귀항·하역 + 어선 스프라이트 | F1 |
| F3 | 어장 비축·회복 + 고갈 UI (G2 문법 이식) | F2 |
| F4 | 바다 출어 + 풍랑·파손 위험 | S5 해안 지형, F3 |
| 후속 | 얼음낚시, 어막 숙식(움막 수상 판), 어선 상위 선급 | — |

## 6. 후속 결정 항목

1. 어부 등급 — 현행 나루터 어부는 보(堡) 유지. 호수·해안의 포구 어부를 촌부터 조건부 해금할지 S4에서 확정
2. 어선 적재 상한과 조업 시간 — F2 실이동 측정 후 확정 (승선 인원은 첫 판 1명 확정)
3. 조난의 수위 — 첫 판은 파손까지, 실종·사망은 재해 확장 때
4. 어장 생성 밀도·회복률 — 수역 크기와 왕복 시간 표본 측정 후 확정
5. 선체 수리 장소 — 포구 응급수리와 배무이터 본수리의 분리 여부
