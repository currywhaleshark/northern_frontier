## 0. 이번 범위의 결과

새 개척 설정에서 소형·중형·대형을 실제 선택할 수 있고, 같은 시드와 같은 크기는 같은 지도를 만든다.
소형은 56×56, 중형은 현행 72×72, 대형은 96×96이다. 기본값과 기존 `newGame()` 호환 경로는
계속 중형을 사용하므로 기존 테스트·도구·저장과 현행 중형 RNG를 바꾸지 않는다.

| 크기 | 치수 | 중형 대비 면적 | 중형 대비 선형 거리 |
|---|---:|---:|---:|
| 소형 | 56×56 | 0.605배 | 0.778배 |
| 중형 | 72×72 | 1배 | 1배 |
| 대형 | 96×96 | 1.778배 | 1.333배 |

## 1. 감사 결과와 확정 결정

1. `CONFIG.map` 값을 선택마다 바꾸지 않는다. 전역 설정 변경은 동시 세션·테스트와 지하 자원 재생성에
   숨은 상태를 만들 수 있으므로 `generateMap(seed, dimensions)`에 명시적으로 치수를 전달한다.
2. `MAP_SIZE_DIMENSIONS`를 새 게임 옵션 계약의 단일 진실원천으로 둔다. 기본 중형만 기존
   `CONFIG.map.width/height`와 일치하는지 테스트한다.
3. `map.ts`의 `blob()`은 전달받은 타일 행렬의 실제 폭·높이를 사용한다. 중형 호출의 난수 호출 순서,
   지형 배치 수식, 시작 중심·근거리 광상 보장은 바꾸지 않는다.
4. 수맥·광맥의 면적 배율은 중형 면적을 기준으로 유지한다. 시작 수맥은 모든 크기에서 같은 치수로
   재생성한 실제 정착지 중심에 맞춘다.
5. 지도 행렬이 런타임의 치수 진실원천이다. 저장 로드 시 56/72/96의 실제 행렬 치수가 저장된
   `worldSetup.mapSize`와 다르면 실제 행렬에 맞춰 보정한다. 이미 v57에 `mapSize`가 있으므로 스키마는
   올리지 않는다.
6. 크기에 따라 시작 인구·물자·이동 속도·위협 증가·습격 전투력을 보정하지 않는다. 더 넓은 총자원과
   긴 이동 거리는 크기 선택의 실제 차이로 둔다. 지역은 S3 전까지 평원만 유지한다.
7. 렌더러·캔버스·미니맵·주민 A*·goal field·습격 경로·탐사·외부 거점은 이미 `state.map`의 실제
   치수를 읽으므로 구조 변경 없이 크기별 회귀만 추가한다.

## 3. 하위 모델 분업

사용량과 충돌을 줄이기 위해 계약을 주 에이전트가 먼저 고정하고, UI와 테스트를 서로 다른 하위 모델에
맡긴다. 하위 모델은 자기 표적 검증만 실행하며 전체 core와 최종 성능 비교는 주 에이전트가 담당한다.

## 4. 성능·밸런스 판정

- 중형은 S1 이전 결과와 지도 전체 deep equality가 유지되어야 한다.
- 대형의 지형 생성·저장 크기는 면적 1.778배에 대체로 비례한다. 72 기준보다 2.5배를 넘는 반복 가능한
  CPU 증가가 나오면 캐시·탐색 범위를 먼저 조사한다.
- 렌더는 viewport 제한이 유지되어야 하며, 대형 전체 면적을 매 프레임 순회하는 새 코드를 추가하지 않는다.
- 시작 물자·인구는 모든 크기에서 같고, 중심지 인근 필수 자원 접근성은 크기와 무관하게 보장한다.
- 총 지형 자원량과 외부 이동 거리는 별도 보정하지 않는다. 실플레이에서 과도하면 S2 후속 밸런스로
  수치 조정하되 이번 계약과 섞지 않는다.
