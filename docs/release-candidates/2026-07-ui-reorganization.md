### 기존 성능 최적화 보존

커밋 `6fba743 perf: stabilize runtime rendering and pathfinding`의 다음 구조가 현재 HEAD에서도
`test_runtime_performance_structure.mjs`로 검증됐다.

- App은 실제 simulation tick이 있을 때만 React version을 올린다.
- `GameCanvas`가 30fps 상한 RAF를 소유하며 정지·숨김 상태에서는 연속 frame을 중단한다.
- renderer는 viewport 영역만 clear/copy하고 건물·주민을 cull한다.
- 탐사 조회는 O(1)이며 `agentsTick`의 중복 탐사 갱신이 없다.
- 광역 목표장은 직업별로 공유하며 기존 A* 힙·통행 memo·실패 cooldown을 유지한다.
- 관련 30일 고정 시드 결정성 테스트가 기준선 전체 테스트에서 통과했다.

최적화 커밋 이후 `GameCanvas.tsx`는 변경되지 않았다. 보호 파일의 후속 변경은
`agents.ts` +22/-6, `renderer.ts` +2/-0의 국소 변경이며 파일 단위 교체는 없었다.

## 5. 완료된 안정화 작업

- **구저장 만족도 완충:** v24 마이그레이션이 만족도 도입 전(v21 이하) 보·진·부 저장에만
  `expectationTransitionUntil`을 한 번 설정한다. 12일 동안 민심 +8을 주며 실제 승격의
  `promotionCheerUntil`과 분리했다. 정착지·새 게임·현재 저장은 제외하고, 저장 후 재로드해도
  기간과 중요 로그가 반복되지 않는다.
- **소년 노동과 서당:** 소년 기본 활동은 `work`/idle이다. 허용 직무는 idle·hauler·farmer·
  woodSplitter·herder이고 성인 효율의 0.5배를 공용 노동 보정에서 한 번만 곱한다. 그 밖의
  직무와 전투·민병·원정 편성은 거부한다. `school`은 일반 작업 슬롯에서 해제되며 완공 서당과
  건강한 훈장이 있을 때 하루 1 진행한다. 24일을 채우고 성인이 되면 clerk와 teacher 기존
  숙련에 각각 0.2를 한 번만 더한다.
- **가족 참조 무결성:** 배열에서 제거되는 특수 주민만 공용
  `detachDepartingResidentFromFamily` 경로를 거친다. 남은 배우자의 `spouseId`를 비우고,
  자녀의 부모 ID를 비우되 `motherName`/`fatherName` 스냅샷을 보존한다. 사망해 배열에 남는
  주민 참조는 그대로 둔다. 로드 정규화가 유효 ID의 이름을 보충하고 고아 ID를 제거한다.
- **전술 명령 팝오버:** 헤더(부대명·인원·현재 열/길목, 수동 표적 배지만 조건부), 최대 3개
  빠른 명령, 고정 마지막 `···`, 기본 접힘 배치 컨트롤로 축소했다. 현재 명령은 버튼의
  `aria-pressed`/활성 스타일로만 보인다. `···`는 팝오버를 닫고 하단 전체 명령판의 첫 버튼에
  포커스를 옮긴다. Esc 포커스 복귀와 방향키 이동을 유지한다.
- **미니맵 렌더 계층:** 겹친 base/overlay canvas를 사용한다. base는 지형 시각 signature,
  탐사, 생활권, 건물 배치·철거·완공, 외부 거점 공개·상태가 바뀔 때만 갱신한다. overlay는
  viewport/resize, 선택, 습격, 원정·사냥 목표, pulse/hover에 반응한다. 클릭·드래그·중심 이동과
  미탐사 정보 비공개를 유지하며 `minimap-base-redraw`/`minimap-overlay-redraw`를 계측한다.
- **화면 전환 오디오:** `screen === 'game'`일 때만 현재 날씨 ambient를 반영한다. 메뉴 전환은
  ambient를 정지하지만 오디오 컨텍스트와 음소거 설정은 재생성·초기화하지 않는다. 전술전의
  기존 별도 효과음 정책은 유지한다.
- **장기 감사·저장 검증:** 16시드 10년 자동 플레이와 11종 저장 마이그레이션 왕복 스크립트를
  추가했다. 구조 실패와 deadline 누락을 테스트 데이터로 분리했다.
- **측정 기반 번들 분할:** 초기 화면에 필요 없는 7개 UI를 `React.lazy`와 유한 오류 fallback으로
  분리했다. 판정 모듈은 UI 청크와 불필요하게 함께 옮기지 않았다.

## 8. 알려진 문제

- 장기 자동 플레이에서 10년 생존은 1/16(6.25%)뿐이었다. 냉사 103명, 아사 49명이며
  최종 평균 인구는 4.88명이다. 구조 오류는 아니지만 병합 승인 전 밸런스 수용 여부를
  명시적으로 판단해야 하는 가장 큰 위험이다.
- 16시드에서 소년 노동일은 491일이었으나 서당일은 0일이었다. 자동 정책은 가동 중인 서당이
  있을 때만 좌석 절반까지 취학시키므로, 대부분의 마을이 서당 운용 단계 전에 붕괴한 결과다.
  서당 선택의 장기 기회비용은 이 표본만으로 판정할 수 없다.
- 지연 로딩 뒤에도 main JS가 850.50 kB라 Vite의 500 kB 경고가 남는다. 더 큰 분할은
  App 전면 분리 없이 실제 구성 측정을 선행하는 후속 작업이다.
- 최종 runtime은 실행 간 편차가 컸고, 최종 HEAD 재실행은 cold와 120명·96동 모두 기준선보다
  15% 이상 느렸다. 같은 코드의 중간 확인 실행에서는 stress가 개선됐으므로 단일 원인은 아직
  분리되지 않았다. 보호된 렌더·경로탐색 구조와 결정성 테스트는 유지되지만 성능 gate는 별도
  반복 계측 전까지 서명할 수 없다.
- 브라우저 자동화 제약으로 창 크기 조절, 3×3 드래그 배치·배치 중 중클릭 패닝, 눈보라 소리의
  실제 청취 등 일부 사람 인수는 직접 완료하지 못했다. 관련 구조/게임 테스트는 통과했지만
  병합 전 실제 입력 장치와 오디오 출력으로 재검증하는 것이 안전하다.

사건 큐는 구현하지 않았다. 현재 하루 호출 순서는
`습격 → 교역 → 귀순/이주 → flavor log → 세공 → 종교 → 특수 주민 → 은맥 → 감찰·견책·토벌
→ 김장 → 예약 특수 사건 → 영토 경고/긴장 → 시나리오`다. 각 시스템의 기존 유효성·모달
게이트와 재시도를 그대로 사용한다. 최장 2일 대기, deadline 누락 0이라는 증거상 직렬화 큐는
복잡성만 늘린다. 이 순서를 명시적 arbitration으로 바꾸는 작업은 계측에서 실제 starvation이나
deadline 누락이 나타날 때만 진행한다.
