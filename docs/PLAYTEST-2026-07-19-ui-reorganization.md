## 관찰사항

### 1. 부패 조건과 입고 직후 손실

- 부패 조건을 전반적으로 조금 완화할 필요가 있다.
- 특히 식량이 생산지나 운반 짐에서 비축으로 들어오자마자 같은 처리 구간의 부패로 깎이는
  동작은 입고 성과가 사라지는 느낌을 준다.
- 후속 확인: 입고 시점과 일일 부패 처리 순서를 먼저 재현하고, 당일 입고분 유예 또는 보관
  조건 완화 중 어느 방식이 기존 부패·보존식 설계를 덜 흔드는지 비교한다.
- 구체적인 완화 수치는 아직 정하지 않는다.
- 수정 완료: 일일 부패는 하루 시작 시점에 이미 있던 재고만 대상으로 삼고, 생산지·운반 짐에서
  당일 입고된 식량은 다음 날부터 부패하도록 1일 유예를 적용했다. 보존식·계절·저장고 수치를
  함께 낮추는 전면 완화보다 문제 지점을 직접 고치는 쪽을 택했다. 스냅숏이 없는 구저장은 불러온
  현재 재고를 기존 재고로 취급해 저장·불러오기로 유예를 중복 획득하지 않는다.

### 2. 건설 드로어 탐색 방식

- 가로 스크롤이 불편하므로 세로 스크롤 방식으로 교체한다.
- 한 화면에 가로 4개 × 세로 2줄 정도가 보이도록 드로어 크기와 카드 배치를 조절한다.
- 현재 건설 가능 건물과 불가능 건물이 뒤섞여 원하는 건물을 찾기 어렵다.
- 후속 방향: 건설 가능 항목을 먼저, 불가능 항목을 뒤에 두되 각 묶음 안의 순서는 안정적으로
  유지한다. 키보드·터치 조작과 잠금 사유 표시는 보존한다.
- 수정 완료: 카테고리 안의 기존 순서는 유지하면서 `지금 건설 가능`과 `현재 불가` 두 묶음으로
  나눴다. 목록은 가로 자동 열 대신 4열 세로 스크롤로 전환해 처음 열었을 때 약 4×2개를 바로
  볼 수 있다. 불가 항목은 잠금 표시와 hover·focus tooltip의 사유를 그대로 유지한다.

### 3. 주민 자동 배치 누락

- 자동 배치가 대부분 작동해도 한두 슬롯이 이유 없이 비는 것처럼 보이는 경우가 있다.
- 후속 확인: 빈 슬롯, 후보 주민의 건강·나이·현재 직업·건물 배정 상태와 자동 배치 실행 전후를
  함께 기록해 후보 필터 문제인지, 반복 중 상태 갱신 문제인지 분리한다.
- 수정 완료: 슬롯 점유 관계와 실제 생산 가능 주민을 분리했다. 자동 배치는 보존된 배정까지 슬롯
  점유로 계산하고, 건강·격리·나이 조건을 통과한 미배정 후보만 빈 슬롯에 넣으므로 표시와 배치
  계산 사이의 이유 없는 공석이 생기지 않는다.

### 4. 와병 주민의 작업 슬롯 유지

- 현재 와병 중인 주민이 배치 슬롯에서 완전히 빠져 버린다.
- 기대 동작: 배정 관계는 슬롯에 유지하고, 와병 중임을 비활성 상태로 표시한다. 회복 전에는
  생산에 기여하지 않되 플레이어가 누구의 자리인지 확인할 수 있어야 한다.
- 후속 확인: 회복 시 자동 복귀, 수동 해제, 자동 배치가 와병 슬롯을 덮어쓸지에 대한 기존
  정책을 확인한 뒤 한 가지 규칙으로 고정한다.
- 수정 완료: 와병·격리·중상 주민은 이름과 배정 슬롯을 유지한 채 `생산 중단` 비활성 상태로
  표시한다. 해당 슬롯은 자동 배치가 덮어쓰지 않으며, 회복하면 같은 자리에서 자동 복귀하고
  수동 해제는 기존처럼 가능하다.

### 5. 다음 교전 급습 적의 조기 표시

- 교전 종료 시점에 다음 교전에서 급습할 예정인 적이 미리 표시됐다가, 명령 단계로 넘어가면
  다시 사라진다.
- 후속 확인: 교전 결과 정리와 다음 교전 초기화 사이에서 적 표시 모델이 잠시 미래 상태를
  읽는지 확인한다. 급습 공개 시점 전에는 무대와 명단 모두 노출되지 않아야 한다.
- 수정 완료: 후열 급습 적은 현재 재생 장계에 자기 `rearAssault` 공개 이벤트가 나타나기 전까지
  숨긴다. 다음 교전의 급습 예정 상태가 이전 교전 종료 화면에 미리 보이지 않고, 실제 공개 박자에
  무대와 명단이 함께 나타난다.

### 6. 프레임 드랍과 다른 미세 끊김

- 기존 최적화 뒤에도 플레이가 미묘하게 뚝뚝 끊기는 느낌이 남는다.
- 단순 평균 FPS 저하보다는 frame pacing, 시뮬레이션 tick, 입력 반응 또는 간헐적 긴 작업일
  가능성이 있다.
- 후속 확인: FPS만 보지 말고 프레임 간격, simulation tick 소요, React commit, canvas draw,
  경로탐색·GC의 긴 표본을 같은 타임라인에서 측정한다. 측정 전 캐시·memo·lazy loading을
  추가하지 않는다.
- 후속 조사 완료: [프레임 페이싱 조사 결과](./PERFORMANCE-2026-07-19-frame-pacing-investigation.md).
  초기 정착지 10배속의 주 병목은 simulation이 아니라 틱마다 발생하는 `App` React 트리 전체
  render→layout commit으로 확인됐다. 첫 갱신 경계 분리 뒤 production frame interval은
  p50 104.2→34.7ms, p95 180.5→62.5ms로 줄었다. 두 번째 snapshot 경계 분리 뒤에는 p50 34.7ms,
  p95 34.8ms를 기록했고, 2.5초 표본의 `App` 전체 commit은 배속 입력에 따른 1회만 남았다.

### 7. 튜토리얼 파종 단계의 계절 불일치

- 장작 수집과 초가집 건설 뒤 파종 퀘스트가 열리면 이미 여름이나 가을인 경우가 많다.
- 그 결과 다음 해까지 기다려야 해 튜토리얼 흐름이 부자연스럽다.
- 후속 방향: 파종 안내를 장작·초가집보다 먼저 배치하거나, 해당 단계를 다음 파종 가능 시기와
  연결해 뒤로 미루는 두 안을 선행 조건과 함께 비교한다.
- 수정 완료: 고정 시드의 정상 진행에서는 주민 선택을 마친 2일차가 아직 봄이므로, 단계 순서를
  `주민 선택 → 파종 → 장작 → 초가집`으로 바꿨다. 다음 파종철까지 대기시키는 안보다 첫해 농사의
  원인과 결과를 바로 보여 주며, 장작·주거 건설이 봄 시간을 먼저 소비하지 않는다.
- 장작 단계 보강: 장작 재고만 목표치에 닿아 안내를 건너뛰지 않도록 `장작마당 1채 완공 + 장작꾼
  1명 배정 + 목표 장작량`을 모두 완료 조건으로 삼았다. 코치도 생산 목록의 장작마당을 먼저 가리킨
  뒤 직업 배정의 장작꾼과 시간 진행을 차례로 안내한다. 단계 의미가 달라져 튜토리얼 버전은 2로 올렸다.

### 8. 매복 사냥꾼과 후열 급습의 처리 순서

- 매복 사냥꾼이 먼저 공격해야 하는 상황에서 후열 급습이 먼저 발생한다.
- 이때 후열의 사냥꾼이 급습 방향으로 돌아본 뒤 전열을 향해 화살을 발사해 연출 순서가
  어색해진다.
- 기대 동작: 매복 사냥꾼의 선제 공격을 먼저 처리한 뒤 후열 급습을 처리한다.
- 후속 확인: 판정과 피해량을 재설계하지 않고 교전 시작 효과의 실행·연출 순서만 재현한다.
- 수정 완료: 새 후열 급습 공개 이벤트를 별도 박자로 만들고, 매복 사냥꾼의 선제 공격 이벤트
  다음에 삽입했다. 피해 판정은 유지하면서 사냥꾼이 전열을 향해 먼저 발사한 뒤 급습 방향을
  바라보도록 실행·연출 순서만 고정했다.

### 9. 묻어 둔 은맥과 노두 고갈

- 은광을 발견한 뒤 묻어 두는 선택을 하면 노두 고갈과 함께 은맥이 사라지는 것처럼 보이며,
  이후 지도나 UI에서 찾을 수 없다.
- 후속 확인: `묻어 둠`, `미공개`, `노두 고갈`, `광맥 고갈` 상태가 같은 표시 조건을 공유하는지
  조사한다. 묻어 둔 은맥은 실제로 소진되지 않았다면 다시 확인할 수 있어야 한다.
- 수정 완료: 묻은 은맥 상태를 원래 석재·철 노두의 잔량과 분리했다. 원광이 0이 되어 평지로
  바뀌어도 탐사한 지도에는 은맥 위치 표식이 남고, 타일 상세에 `묻어 둠 · 원광 고갈 · 다시 열
  수 있음`을 표시한다. 담당 채광장에서는 계속 `묻어 둔 은맥을 다시 연다`를 실행할 수 있다.

### 10. 묘지 안치 기록 확인

- 묘지에 안치된 시신의 이름, 사인, 사망일자를 확인할 수 있으면 좋겠다.
- 후속 확인: 기존 시신·주민 기록에 세 정보가 보존되는지 먼저 확인하고, 저장 자료형을 늘리지
  않아도 된다면 묘지 선택 정보에 표시만 추가한다. 구저장에 값이 없을 때는 `미상`으로 처리한다.
- 수정 완료: 시신에는 세 값이 있었지만 안치 순간 시신 배열에서 제거되며 정보가 사라지는 것을
  확인했다. 묘지 건물에 이름·사인·사망일·안치일의 최소 기록을 보존하고 선택 정보에서 묘 자리와
  함께 표시한다. 기록 없이 묘 수만 남은 구저장은 묘 수만큼 `미상` 기록으로 보완한다.

### 11. 주민 목록 필터와 정렬

- 인구가 늘어날수록 주민 목록에서 원하는 주민과 상태를 찾기 어렵다.
- 주민 목록에 필터와 정렬 기능이 필요하다.
- 후속 확인: 현재 목록이 제공하는 나이 단계·직업·건강·배정 정보 중 실제 탐색에 필요한 최소
  필터와 정렬 기준을 정하고, 선택 주민과 스크롤 위치가 불필요하게 초기화되지 않게 한다.
- 수정 완료: 이름 검색, 직업, 상태(건강 주의·근무지 없음·아이/소년·특수 주민·사망) 필터와
  입주·이름·건강·직업·근무지 정렬을 추가했다. 행에는 근무지 배정 상태도 보인다. 필터는 선택
  주민 ID나 목록 scrollTop을 초기화하지 않으며, 숨겨진 선택은 안내 문구로만 알린다.

## 다음 작업일의 공통 원칙

1. 각 항목은 먼저 최소 재현 절차와 실패 회귀 테스트를 만든다.
2. 부패와 전투 순서처럼 결정적 결과에 영향을 줄 수 있는 변경은 최초 발산 지점을 기록한다.
3. 미세 끊김은 실제 timing 자료를 확보하기 전까지 최적화 방식을 정하지 않는다.
4. 이번 메모의 항목을 새 콘텐츠 추가나 전투 밸런스 전면 조정으로 확대하지 않는다.
