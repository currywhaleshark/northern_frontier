## 0. 이번 범위의 결과

새 게임 설정에서 호수를 선택할 수 있다. 세 지도 크기 모두 하나의 큰 연결 호수를 포함하며, 호반은
강과 같은 자연 급수권을 제공하고 농수로의 취수원이 된다. 수면이 넓은 만큼 가용 육지가 줄고,
숲·지표 광상·지하 광맥도 평원보다 적어 농업과 수리에는 유리하지만 목재·광업에는 불리하다.

호수에는 홍수가 없다. 초겨울에는 호숫가부터 안쪽으로 얼어 겨울 6일째(한겨울) 전면 결빙하고,
봄에는 호숫가부터 다시 녹아 봄 6일째(봄 중순) 완전 해빙한다. 실제로 얼어 있는 호수 타일만
도보 통행할 수 있다. 강의 방향성 물비늘은 호수에 적용하지 않고, 액체 상태인 호숫가 경계에서는
호수 안쪽으로 짧은 잔물결 띠가 퍼졌다 사라진다.

어선·배무이터·포구·수상 항행·어장 비축·하역은 이 단계에서 만들지 않는다. S4가 확정하는
`lake` 지형·저장·통행 계약을 바탕으로 어선 설계 F0 이후에서 구현한다.

## 1. 확정한 의미 경계

문자열 `river`를 전역 치환하지 않는다. 물의 의미를 다음처럼 분리한다.

| 의미 | river | lake |
|---|---:|---:|
| 자연 급수권 반경 3 | O | O |
| 논의 자연 관개·농수로 취수 | O | O |
| 소방용 자연수 | O | O |
| 액체 상태 육상 통행 차단 | O | O |
| 결빙 도보 통행 | 겨울 일괄 규칙 | 타일별 결빙 진행도에 따라 허용 |
| 강 흐름 물비늘 | O | X |
| 호숫가 안쪽 잔물결 | X | O |
| 보·제방·물레방아·다리·나루터 | O | X |
| 봄 홍수·보 저수지·제방 파손 | O | X |

공통 판정은 `isNaturalWaterTerrain(terrain)`과 흐르는 강 전용 판정을 두어 호출부의 의도를
드러낸다. 물가 오토타일은 river와 lake가 맞닿을 때 가짜 둑이 생기지 않도록 둘을 하나의 수면으로
보되, 애니메이션과 시설 규칙은 위 표대로 분리한다.

호수의 결빙장은 저장 상태가 아니라 날짜와 호수 지형에서 결정적으로 계산한다. 각 lake 타일의
호숫가까지 4방향 거리를 캐시하고 다음 규칙을 적용한다.

- 겨울 1~6일: 거리 0인 가장자리부터 최대 수심 거리까지 결빙 경계가 안쪽으로 전진한다.
- 겨울 6~12일: 모든 lake 타일이 얼어 있다.
- 봄 1~6일: 거리 0인 가장자리부터 해빙 경계가 안쪽으로 전진해, 깊은 중앙 얼음이 마지막에 녹는다.
- 봄 6~12일과 여름·가을: 모든 lake 타일이 액체 상태다.
- 날씨 RNG는 결빙장을 바꾸지 않는다. 저장·로드와 같은 날짜의 결과가 항상 같아야 한다.

## 2. 지도와 자원 프로필

수치는 첫 구현·다중 시드 회귀의 기준선이며 실화면 표본에서 한 번 조정할 수 있다.

| 축 | 평원 기준 | 호수 S4 초안 |
|---|---:|---:|
| 큰 호수 | 없음 | 하나의 4방향 연결 수역, 전체 면적 약 16~22% |
| 숲 blob | 26 | 18(약 69%), 중심 연결 육지에 초반 벌목 가능 숲 최소 보장 |
| 가장자리 산 blob | 동 10·북 6 | 동 7·북 4 |
| 지표 광상 확률 | 산자락 0.25 | 0.15, 근거리 돌·철 각 1곳 보장은 유지 |
| 지하 광맥 | 광종별 기준 | 개수 0.8배·반경 0.85배·용량 0.8배 |
| 일반 수맥 | 기준 | 개수 1.2배·반경 1.1배·용량 1.15배 |
| 호반 비옥지 | 강 2칸 내 0.55 | 자연수 2칸 내 0.65 |

- 호수는 기존 강 생성 뒤 호수 지역에서만 별도 RNG를 소비해 판다. 평원·산지의 같은 시드 결과와
  RNG 소비 순서는 바꾸지 않는다.
- 호수는 지도 경계와 정착지 중심을 끊는 장벽이 되지 않도록 폐쇄형 큰 수역으로 만들고, 중심 후보와
  3×2 중심지·둘레 한 칸은 육지로 보장한다.
- 중심에서 연결된 건설 가능 육지, 즉시 놓을 수 있는 시작 우물, 도달 가능한 근거리 돌·철, 활성
  서식지 하나, 초반 벌목 가능 숲은 유지한다. 부족은 시작 불능이 아니라 총량과 확장 선택의 제약이다.
- 넓은 수면 때문에 평지와 육상 서식지 총량이 자연스럽게 줄어든다. 호수 어장은 F3 전까지 생성하지
  않는다.

## 3. 호숫가 잔물결 렌더 계약

1. 정적 수면·물가 오토타일은 기존 강 수면 자산을 재사용하되 자연수 공통 함수로 이름과 판정을
   일반화한다. 신규 PNG는 필수 조건이 아니다.
2. `drawRiverFlow`는 계속 river만 순회한다. lake를 방향장이나 강 흐름 캐시에 넣지 않는다.
3. 호수 잔물결은 별도 순수 계산에서 호숫가의 N/E/S/W 경계와 물 안쪽 법선을 구한다.
4. 각 경계에 해안선과 평행한 2~3개의 짧은 곡선을 두고, 좌표 해시와 시간 위상으로 해안에서
   3~18px 안쪽으로 퍼졌다 투명해지게 한다. 저장 RNG와 시뮬레이션 상태는 소비하지 않는다.
5. 미답사 수면은 그리지 않고 viewport를 지킨다. 얼어 있는 타일에는 잔물결을 그리지 않으며,
   부분 결빙·부분 해빙 중에도 강의 흙탕물 흐름을 적용하지 않는다.

사용량을 아끼되 최종 판단과 통합은 주 에이전트가 맡는다.

- 하위 A (`gpt-5.6-terra / medium`): 지형 타입·생성·통행·렌더 접점 감사와 호숫가 잔물결 제안
