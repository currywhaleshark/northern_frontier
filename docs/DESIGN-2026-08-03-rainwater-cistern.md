# 빗물 저수조 설계 — 해안·산지의 물 부족 완화 시설

> **계획 상태:** 미착수 (2026-08-03 사용자 구술 확정 — 구현계획 미작성)
> **상태 갱신:** 2026-08-03 — 작은 단일 시설 설계. [새 게임 설정](DESIGN-2026-08-01-new-game-setup.md) S3 산지·S5 해안의 물 부족 의도를 유지한 채 완화 수단만 준다.

- 작성일: 2026-08-03

## 0. 목적과 경계

해안·산지는 **설계 의도상 수자원이 부족하다**(해안: 바닷물 비음용·수맥 희박, 산지: 하천 접근 제약). 이 의도를 없애지 않으면서 플레이어에게 **대응 수단**을 준다.

**핵심 원칙: 우물의 대체재가 아니라 보완재.** 비가 올 때 받아 두었다가 쓰는 시설이라 —
- 평시에는 급수의 일부를 메워 숨통을 틔우고,
- **가물면 먼저 마른다** — 가뭄 때 오히려 위험이 커지는 구조라, 이것만 믿고 마을을 키우면 대가를 치른다.

## 1. 현재 기준선 (2026-08-03 코드 대조)

- 급수 모델(`waterSupply.ts`): 건물별 `demand`(주거는 잠자리당 0.3, 가죽공방 4, 옹기가마 1.5, 의원 2, 축사 마리당 0.25)를 공급원이 공정 배분(`fair share`)으로 채운다. 공급원은 `river`·`lake`·`canal`·`well`.
- 우물은 수맥 저수위(`level/capacity`)에서 하루 `wellDailyOutput`(12)을 뽑고, 수맥은 매일 회복한다 — **비·눈이 오면 회복 보너스**(`aquiferRainRecoveryBonus` 6, `aquiferSnowRecoveryBonus` 2). 즉 "비가 물을 채운다"는 문법이 이미 있다.
- 가뭄(`isDroughtActive`)은 이미 급수 계산에 관여한다.
- 날씨는 결정적 연간 기후에서 나오고 일별로 확정된다 — 강우 판정에 새 난수가 필요 없다.

즉 **신규 공급원 종류 하나 추가**가 이 설계의 거의 전부다. 저수·회복·배분·UI 문법이 모두 있다.

## 2. 시설 — 빗물 저수조 (가칭)

| 항목 | 초안 |
|---|---|
| 이름 | 빗물 저수조 (물두멍/봇도랑 아님 — 지붕물받이 + 독) |
| 등급 | 촌(1티어) — 초반 해안·산지의 숨통이 목적 |
| 배치 | 육상. 수맥 불요 — **우물을 못 파는 곳에 놓을 수 있다는 점이 존재 이유** |
| 비용 | 목재·옹기 위주 소량 (초안: 목재 4·옹기 2·석재 2, 공기 3일) — 우물(목재 4·석재 6·도구 1, 4일)보다 싸고 도구가 안 든다 |
| 슬롯 | 0 (무인 — 우물과 같다) |
| 급수 반경 | 우물(6)보다 좁게 — 초안 3~4칸. 마을 한복판의 국지 보완 |

### 저수·소모 규칙

- 자체 저수량 `stored / capacity`를 갖는다 (초안 용량 30 안팎 — 주거 몇 채의 며칠분).
- **비·눈 오는 날 채워진다**: 강우 강도에 비례해 `stored` 증가(초안 비 8/일, 눈 3/일). 지붕 면적 개념 대신 시설 자체 상수로 단순화.
- **하루 공급 상한**이 있다(초안 6/일) — 저수가 남아도 하루에 그 이상은 못 준다. "받아 둔 물을 아껴 쓴다"는 감각.
- 우물보다 **공급 우선순위가 낮다**(또는 동급) — 우물이 닿는 곳에서는 저수조가 놀고, 수맥이 못 미치는 변두리를 메운다. 배분 세부는 구현 시 `fair share`와 맞춰 결정.
- 겨울: 얼면 공급 정지 또는 감소 — 눈은 쌓이되 녹아야 쓴다(초안: 겨울 공급 절반, 봄 첫날 눈 저장분 해빙 가산). 결빙 문법은 호수 결빙(`lakeIce`) 선례 참고.

### 가뭄 리스크 (핵심)

- 무강수일이 이어지면 저수가 그냥 줄어든다 — 회복원이 비뿐이라 **가뭄에 가장 먼저 바닥난다.**
- 가뭄 중에는 증발로 소폭 추가 감소(초안 -1/일)를 둔다. 우물(수맥은 느리게라도 회복)과의 성격 차이를 분명히 하는 장치.
- 저수가 바닥나면 경고 로그 + 급수 부족의 기존 결과(사기 하락·발병 확률)가 그대로 온다. 새 페널티를 만들지 않는다.

## 3. 지역별 의도 유지

| 지역 | 저수조의 값어치 |
|---|---|
| 해안 | 수맥이 희박한 곳의 주거 급수를 메운다. 다만 가뭄에 취약해 **자염(장작)·교역과 함께 굴려야** 안정 — 해안의 "물은 귀하다" 의도는 유지 |
| 산지 | 하천이 먼 고지대 마을의 국지 보완. 강우 자체는 적지 않으므로 초반 효과가 크다 |
| 평원·호수 | 지을 수는 있으나 이득이 작다(이미 강·수맥이 넉넉) — 지역 정체성이 흐려지지 않는다 |

## 4. 단계 (한 라운드)

| 단계 | 내용 |
|---|---|
| W1 | 건물 정의 + `stored/capacity` 상태 + 일일 강우 적립·가뭄 감소 + 급수원 편입(`WaterSupplySource`에 `cistern` 추가) + 저장 마이그레이션 |
| W2 | UI: 선택 시 저수량·예상 며칠분 표시, 수맥 레이어에서 저수조 급수권 표시, 바닥 경고 |
| W3 | 스프라이트(계절 변형 불요 — 겨울 결빙 표현만) + 초회 도움말(guides) 모듈 |

밸런스 수치는 전부 `CONFIG.water`에 두어 **밸런스 편집기로 조정 가능**하게 한다.

## 5. 경계

- **우물 대체 금지**: 반경·하루 상한·가뭄 취약성 셋이 동시에 이 선을 지킨다. 저수조 스팸으로 수맥 없이 대형 마을이 굴러가면 실패 — W1 후 실측으로 확인한다.
- 화재 진화용 물(물동이)과의 관계: 첫 판에서는 **소방 용도 제외**(우물만) — 확장하면 저수조가 만능이 된다. 후속 결정.
- 논·밭 관개에는 쓰지 않는다 — 생활용수 전용. 농업용수는 농수로·보의 몫.

## 6. 후속 결정 항목

1. 공급 우선순위 — 우물보다 낮게 vs 동급 (구현 시 `fair share` 실측)
2. 겨울 처리 — 공급 절반 vs 완전 정지 + 봄 해빙 가산
3. 소방 용도 편입 여부 (권고: 1차 제외)
4. 이름 확정 — 빗물 저수조 / 물두멍 / 우수통 중 고증 검토
5. 축사·작업장 급수 허용 범위 (초안: 주거 우선, 전부 허용)
