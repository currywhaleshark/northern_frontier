## 2. 공통 기반 — 지연 판정

### 2-1. 문제

현재는 선택 → 즉시 주사위 → 즉시 결과다. "기다린다"를 골라도 기다림이 없다.

### 2-2. 원칙

**선택은 즉시, 결과는 나중에.** 재해마다 지연의 형태가 다르다.

| 형태 | 방식 | 적용 |
|---|---|---|
| **날씨 추적형** | 판정 기간 동안 **실제 날씨표의 일수**를 세어 결과 확정 | 이른 서리 · 늦서리 |
| **일일 누적형** | 매일 피해가 조금씩 쌓이고, 종료일은 미리 정해져 있으나 비공개 | 황충 · 가뭄 · 역병 · 가축 돌림병 |
| **단발 지연형** | 발생 자체가 조건 충족일에 터짐 (선택 없음 또는 사후 선택) | 대홍수 · 설해 |

날씨 추적형이 핵심이다. 선행작업으로 날씨표가 결정적이 되므로, "기다린다"의 결과를
숨은 주사위가 아니라 **화면에 실제로 지나가는 날씨**로 판정할 수 있다. 서리가 하루하루
이어지는 걸 보며 플레이어가 초조해지는 것 — 그것이 지연 판정의 목적이다.

측우기(하사품 문서 §6)가 보여 주는 확률은 기후 공식에서 나오고, 실제 판정은 그 기후가
만든 날씨표를 따르므로 **표기 확률과 실제 분포가 같은 원본을 공유**한다. 개별 연도의
결과는 세계 생성 시점에 정해져 있지만 플레이어가 미리 알 방법은 없다 (하사품과 같은 철학).

### 2-3. 상태 구조

```ts
// types.ts
export interface PendingDisaster {
  id: DisasterId;              // 'earlyFrost' | 'lateFrost' | 'locust' | ...
  choiceId: string;            // 플레이어 선택 ('wait-harvest' 등)
  startedDay: number;
  resolveDay: number;          // 판정일 또는 종료 예정일
  targetBuildingIds?: number[];
  progress?: number;           // 일일 누적형의 누적 피해
  data?: Record<string, number>;
}

// GameState
pendingDisasters: PendingDisaster[];
```

- 처리는 `simulation.ts`의 일일 처리(자정)에 `advancePendingDisasters(state)` 한 곳
- 세이브 버전 +1. 구세이브는 빈 배열 — 마이그레이션 사실상 무비용
- 진행 중 재해는 통합 로그와 상단 경보(`AlertsPanel`)에 "황충 창궐 중 · 4일째" 형태로 노출

## 3. 재해 목록

### 3-1. 이른 서리 (개편)

- 발생: 가을, **날씨표의 서리일 근처에 정렬**해서 발생 (기후와 어긋난 서리 이벤트 금지)
- 선택: `조기 수확` (즉시 절반 — 기존 로직 유지) / `기다린다`
- **기다린다 판정 (날씨 추적형)**: 이후 4일간 날씨표의 `frost + coldSnap` 일수 ≥ 2 → 실패
  (소출 대부분 손실), 미만 → 정상 수확. 58% 하드코딩 제거
- 측우기: 그해 기후로 계산한 성공 확률을 문구에 표기 (하사품 문서 §6의 공식 유지 —
  단 판정은 rng가 아니라 날씨표를 센다. 공식은 UI 근사치)
- 시각효과: 대상 경작지 타일에 서리 백화(白化) 오버레이 — 판정 기간 내내

### 3-2. 늦서리 (신규)

봄 파종 직후 서리가 내려앉는다. 이른 서리의 봄 거울상.

- 발생: 봄 중후반, 파종된 밭 존재 + 날씨표의 봄 서리일에 정렬
- 선택:
  - `갈아엎고 여름 작물을 심는다` — 확실. `sownArea`·`fieldGrowth` 리셋 후
    해당 밭의 작물을 여름 파종 작물로 전환 (메밀 등 `plantSeasons: ['summer']` 실재 —
    역사적으로도 메밀이 구황 재파종 작물이다). 봄 성장분은 잃는다
  - `기다린다` — 날씨 추적형. 이후 3일간 서리 일수로 회복/고사 판정
- 시각효과: 이른 서리와 공유

### 3-3. 황충 (신규)

- 발생: 여름~초가을. 발생 가중치 ← 온도·강수 조합 (기후 문서 §6)
- **일일 누적형**: 메뚜기 떼가 머무는 동안 매일 경작지 성장도가 깎인다.
  체류 기간은 발생 시 결정(2~5일)하되 비공개 — 플레이어는 매일 줄어드는 밭을 보며 결정한다
- 선택 (경작지별이 아니라 정착지 단위 1회):
  - `서둘러 거둔다` — 남은 성장도의 절반 즉시 확보 (이른 서리 조기 수확 로직 재사용)
  - `버틴다` — 떼가 떠날 때까지 감수
- 시각효과: 경작지 위 메뚜기 떼 입자 오버레이 — 렌더러에서 체류 기간 내내
- 역사 각주: 실록의 황충(蝗蟲) 기사가 많다. 북방에도 기록이 있어 배경과 맞다

### 3-4. 가뭄 (신규) — 대비: 보(洑)

- 발생: `precipitationAnomaly`가 낮은 해의 여름, 날씨표의 실제 무강수 구간에 정렬.
  **선포식**: "가뭄이 들었다" 로그 + 경보. 선택지는 없다 — 대비는 건물(보)로 미리 한다
- **일일 누적형**: 지속 기간(6~12일, 비공개) 동안
  - 밭·논 성장 배율 하락 (비 보너스 소실 + 추가 페널티)
  - 어부 어획 하락 (강 수위)
  - 우물이 없으므로 식수는 다루지 않는다 (화재·급수와 함께 후속)
- 종료: 기간 만료 또는 **날씨표에 비가 오면 즉시 해소** — 비를 기다리는 긴장이 자연스럽게 생긴다
- **보(洑)**: 강 위에 짓는 단칸 건물 (다리와 같은 `placement: 'river'`).
  반경 N칸의 밭·논이 가뭄 페널티를 절반(또는 면제)으로 받는다.
  역사적으로 보는 조선 관개의 기본 시설 — 진(鎭) 이전 등급에서도 지을 수 있게 해
  가뭄 대비가 초중반 선택지가 되게 한다

### 3-5. 해빙기 대홍수 (신규) — 대비: 제방

평범한 `thawFlood` 날씨(통행 차단)와 별개로, 조건이 겹친 해에만 **대홍수**가 터진다.

- 발생: 기후 문서 W5의 값 그대로 — 직전 겨울 적설일 多 + 봄 온난. 해빙기 홍수 날씨일에 발생
- 효과 (단발 지연형 — 발생 자체가 예고 없이):
  1. **범람**: 강에서 BFS로 1~2칸(심도는 그해 조건)까지 물에 잠김.
     `tile.terrain`은 바꾸지 않는다 — 렌더러 오버레이 + 통행 불가 처리.
     잠긴 칸의 주민은 기존 `ensureResidentOnPassableTile`이 자동 대피시킨다
  2. **건물 파손**: 잠긴 칸 위 건물 + `placement: riverbank/river` 건물(나루터·부두·방앗간·다리)이
     확률 파손 — `damageBuildings` 패턴을 대상 지정형으로 재사용
  3. **작물**: 잠긴 논·밭 성장도 손실
  4. **퇴적 보상**: 물이 빠진 뒤(1~2일) 잠겼던 평지 일부가 `terrain: 'fertile'`로 전환.
     범람원이 기름진 역사 그대로 — "강변은 위험하지만 기름지다"는 입지 긴장이 이 재해의 핵심
- **제방(堤防)**: 목책(`palisade`)과 같은 단칸 구간형. 강에서 2칸 이내 땅에만 배치.
  범람 BFS가 제방 칸을 통과하지 못한다 — 제방 뒤편은 잠기지 않는다.
  통행은 가능(둑 위를 걷는다). 방어도는 없다.
  퇴적 보상도 제방 뒤에는 오지 않는다 — 보호와 비옥화는 교환 관계다

### 3-6. 설해 (신규)

- 발생: 겨울, 날씨표에서 `heavySnow + blizzard` 연속 2일 이상인 구간 직후 판정
  (날씨표가 결정적이라 미리 계산 가능 — 별도 적설 상태 불필요)
- 효과: 주거 건물 지붕 붕괴 확률 판정 → `damageBuildings` 패턴
  - 움집(hut): 높음 / 온돌집: 낮음 / 기와집: 면제
- **대비 = 주거 티어 업그레이드.** 새 시스템 없이 기존 업그레이드에 의미를 얹는다.
  선택지 없는 재해 — 대비했으면 지나가고, 안 했으면 무너진다
- 입주자가 있는 건물이 무너지면 `reconcileResidentHomes`가 재배치 (파손 패턴에 이미 포함)

### 3-7. 역병 강화 (개편)

현재 개별 질병은 남긴다 (평상시 배경). 별개로 **역병(疫病) 재해**를 추가한다.

- 발생: 여름 가중 + 인구밀도·노숙자 수 가중
- **일일 누적형**: 최초 감염자 발생 → 매일 같은 집·같은 작업장 주민에게 전염 판정.
  약초 재고·의원 수·진료소가 전염률과 회복률을 좌우
- 선택:
  - `격리령` — 감염자와 동거인 전원 `quarantinedUntil` 처리. 노동력 손실이 크지만 확산 차단
  - `그대로 둔다` — 노동 유지, 확산 위험. 사망자가 나올 수 있다
- 종료: 신규 감염 0이 이틀 지속되면 해소 선언
- 지금 대응이 쉬운 이유는 회복(약초 28%/일)이 감염(0.2%/일)을 압도하기 때문 —
  역병 기간에는 감염이 회복을 앞지르는 균형으로 설계한다. 의원·진료소의 존재 이유가 생긴다

### 3-8. 가축 돌림병 (신규)

한 시스템, 축종군별 시대 명칭. **조류독감은 근대 개념이므로 계역(鷄疫)으로 쓴다.**

| 발현명 | 대상 축종 | 비고 |
|---|---|---|
| **우역(牛疫)** | 소 · 양 · 염소 | 실록에 다수 기록된 실재 용어. 쟁기 소가 죽으면 농사 타격 |
| **저역(猪疫)** | 돼지 | |
| **계역(鷄疫)** | 닭 | |
| **마역(馬疫)** | 말 | 군마 손실 — 군사적 타격. 실록에 기록 있음 |

- 발생: 사육 중인 축종군 중 가중 추첨 (두수 많은 쪽이 약간 더 위험)
- **일일 누적형**: 감염 축사에서 매일 폐사 판정, 같은 축종군의 다른 축사로 전염 가능
- 선택:
  - `도살 처분` — 감염 축사 두수의 일정 비율 즉시 도살 (고기·가죽 일부 회수), 확산 종료
  - `격리하고 버틴다` — 목동이 간호. 자연 종식을 기다리되 전멸 위험
- 도살은 기존 `slaughterLivestock` 경로 재사용

### 3-9. 갱도 붕괴 (신규 — 채광갱 도입과 함께)

채광갱(`DESIGN-2026-07-28-deep-mining.md`)이 있는 한 필연인 재해. 지하를 여는 대가다.

- 발생: **가동 중인 채광갱에서만.** 가중치 두 축 —
  - **깊이**: 광맥 잔량이 낮을수록 위험 (빈 맥을 쥐어짤수록 깊이 판다는 설정.
    말라 가는 광맥의 마지막 한 줌이 가장 위험한 광석이 된다)
  - **물**: 비·해빙기 홍수 날씨일에 가중 (지하수 침투 — 날씨표 연동)
- **전조**: 붕괴 며칠 전 확률적 경고 — "갱목이 우는 소리가 난다" 로그 + 경보.
  플레이어 대응은 **기존 작업 슬롯 해제** 그대로다: 채광꾼을 빼면 인명은 안전하지만
  생산이 멎는다. 전조가 항상 오지는 않는다 (온 것을 무시한 대가와, 오지 않은 불운은 다르다)
- 발생 시:
  - 갱 안에서 근무 중이던 채광꾼 **매몰**
  - 건물 파손 (`damageBuildings` 패턴)
- **구조 (지연 판정 — 일일 누적형)**: 선택지가 구조의 속도다
  - `서둘러 판다` — 이틀. 빠르지만 2차 붕괴 위험 — 구조 인력(건축가·채광꾼)이 다칠 수 있다
  - `조심스럽게 판다` — 나흘. 안전하지만 매몰자 생존 판정이 매일 깎인다
- 매몰자는 구출 시 부상 상태(기존 `injure` 패턴) — 약초·의원이 회복을 좌우.
  생존 판정에 실패하면 `killResident` (사인: 갱도 붕괴)
- 등록부에는 발생 가중치만 올린다 — 구조 성공률은 기후와 무관하므로 측우기 대상이 아니다

### 3-10. 화재 — 보류

넣고 싶은 재해지만 **우물·급수 시스템이 선행**이다. 진화(消火)가 없는 화재는 대응 수단이
없는 일방 피해라 재미가 없다. 우물 도입 때 함께 설계한다.
(그때 대장간·숯가마·염초장이 발화원, 건조한 해 가중, 인접 확산, 주민 급수 진화가 한 묶음)

## 4. 새 건물 요약

| 건물 | 배치 | 원형 | 효과 |
|---|---|---|---|
| **보(洑)** | 강 위 단칸 (`river`) | 다리 | 반경 내 밭·논 가뭄 페널티 절반~면제 |
| **제방(堤防)** | 강 2칸 이내 땅, 구간형 | 목책 | 범람 차단. 통행 가능. 뒤편은 퇴적 보상도 없음 |

## 5. 시각효과 (렌더러)

| 재해 | 효과 | 비고 |
|---|---|---|
| 대홍수 | 잠긴 칸 물 오버레이 (수면 애니메이션) | 지형 불변, 오버레이만 |
| 이른·늦서리 | 대상 경작지 백화 오버레이 | 판정 기간 내내 |
| 황충 | 경작지 위 벌레 떼 입자 | 체류 기간 내내 |
| 가뭄 | 경작지 건조 틴트 (선택) | 우선순위 낮음 |

렌더러 소유권 경계(전투확장 2단계 체제)를 따른다 — 그리기는 `renderer.ts`,
상태·판정은 게임 로직 쪽. 렌더러는 `state.pendingDisasters`를 읽기만 한다.

## 6. 재해 등록부 연동

모든 재해는 하사품 문서 §6의 등록부에 등록한다.

- `disasterOccurrenceWeight(state, id)` — 발생 가중치 (기후값 사용)
- `disasterChoiceChance(state, id, optionId)` — 선택지 확률 (측우기 표기용)
- 날씨 추적형의 실제 판정은 날씨표를 세지만, 표기 확률은 이 함수로 계산한다
- 수치는 전부 `CONFIG.disasters`에 — 이벤트 코드에 숫자를 직접 쓰지 않는다

## 7. 구현 순서

| 단계 | 내용 | 의존 |
|---|---|---|
| D0 | `pendingDisasters` 상태 + `advancePendingDisasters` + 세이브 +1 + 경보 표시 | W1~W4 |
| D1 | 이른 서리 지연 판정 전환 + 서리 시각효과 | D0 |
| D2 | 늦서리 (이른 서리 변형 + 여름 작물 전환) | D1 |
| D3 | 황충 (일일 누적 + 벌레 떼 시각효과) | D0 |
| D4 | 가뭄 + 보(洑) | D0 |
| D5 | 대홍수 + 제방 + 범람 시각효과 + 퇴적 | D0, W5 |
| D6 | 설해 | W1~W4만 |
| D7 | 역병 강화 | D0 |
| D8 | 가축 돌림병 | D0 |
| D9 | 갱도 붕괴 | D0, 채광 문서 M3 |

D1~D8은 D0 이후 대부분 상호 독립 — 작업자가 나눠 맡을 수 있다.
권장 첫 묶음은 **D0+D1** (기존 이벤트의 전환이라 가장 안전한 검증대).

### 구현 기록

- [x] D1 — 이른 서리 실제 날씨 추적 판정·경작지 백화
- [ ] D2~D9 — 후속 재해와 대응 건물

## 8. 열어 둔 판단

- 이른·늦서리 판정 기간(4일/3일)과 실패 문턱(서리 2일) — 첫 플레이테스트 대상
- 보·제방의 반경/차단 규칙 세부 — 특히 제방이 몇 칸 깊이 범람까지 막는지
- 퇴적 비옥화의 양 — 너무 후하면 홍수를 기다리는 플레이가 된다 (잠긴 평지의 20~30%쯤에서 시작)
- 역병 균형 — 격리령의 노동 손실이 며칠이면 "항상 격리"가 정답이 되지 않는지
- 가축 돌림병의 축종군 전염 범위 — 우역이 양·염소까지 번지는 게 두수 기준으로 과한지
