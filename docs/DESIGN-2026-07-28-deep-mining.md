# 채광갱과 지하 광맥 — 설계

- 작성일: 2026-07-28
- 발단: 노두(露頭)는 유한하다 — 장기 플레이에서 바위 광상이 전부 소진되면 채광이 영구히 끝난다
- 범위: 지하 광맥 레이어 + 채광갱(부 승격 후) + 광물 레이어 UI
- 연관: `DESIGN-2026-07-28-wells-and-water.md`의 수맥 프레임워크 **공유**
- 구현: 다른 작업자 인수인계 전제

## 1. 문제 — 노두는 끝난다

| 사실 | 근거 |
|---|---|
| 돌·철 광상 모두 유한 | `tile.mineralRemaining` — 돌 `stoneMin~Max`, 철 `ironMin~Max` (`minerals.ts`) |
| 재생 없음 | 소진된 바위는 `trace` 티어로 남고 끝 |
| 채광장은 노두 전용 | 반경 `mineWorkRadius` 내 바위 타일만 캔다 (`miningSites.ts`) |

나무는 재성장하고 식량은 농사로 돌지만 광물만 막다른 길이다.
부(府) 이후의 장기 플레이에 **지하**를 연다.

## 2. 지하 광맥 — 수맥 프레임워크 재사용

우물 문서 §1의 수맥과 **같은 기하 모델**을 쓴다. 구현 시 공용 헬퍼로 묶는다.

```ts
// 수맥(aquiferVeins)과 공유하는 패턴 — 시드 순수 함수, 저장 안 함
interface OreVein {
  id: number;
  mineral: 'iron' | 'stone';
  cx: number; cy: number;    // 중심 (가장 짙은 곳)
  radius: number;
  capacity: number;          // 광맥 전체 매장량 (수맥과 달리 회복 없음)
}
export function oreVeins(seed: number, mapW: number, mapH: number): OreVein[];
oreRichnessAt(seed, x, y): { mineral, richness } | null
```

- 수맥과의 결정적 차이: **광물은 회복되지 않는다.** 수위 대신 잔량이다
- 지표 지형과 무관하게 깔린다 — 평지 밑에도 광맥이 있다 (노두는 광맥이 드러난 곳이라는 설정)
- 철맥·석맥은 별개 지대. 겹치면 철 우선 표시
- 은은 넣지 않는다 — 은은 잠채·설점·조정 의심이라는 정치 시스템에 묶인 지표 자원으로 유지

### 잔량 상태

```ts
// GameState — 세이브 +1, 구세이브는 전 광맥 만재로 시작
oreVeinRemaining: number[];   // 광맥 id 순
```

같은 광맥 위 채광갱 여럿은 잔량을 공유한다 (수맥의 수위 공유와 동일 규칙).

## 3. 광물 레이어 — 수맥 레이어와 같은 2단계

| 조건 | 보이는 것 |
|---|---|
| 기본 (누구나) | 광맥 **범위와 종류** — 철은 녹슨 적갈색, 석재는 회색의 균일한 옅은 칠 |
| **허생 재촌** | **농담** — 풍부도 비례 짙기. 짙은 곳 = 중심 = 채광갱 최적지 |

- `uiPrefs`에 `showOreLayer` 토글 (수맥 `showAquiferLayer`와 나란히)
- **채광갱 배치 모드에서 자동 표시**
- 답사(`isExplored`)한 칸에서만 보인다 — 안개 규칙과 일관
- 허생의 소개문에 이미 "바위의 맥을 짚는 지관"이라 적혀 있다 — 수맥·광맥 정밀 관측을
  같은 능력 갱신으로 묶는다 (우물 문서 §1-2와 함께 한 번에)

## 4. 채광갱(採鑛坑)

| 항목 | 값 |
|---|---|
| 등급 | **부(府)** — 후반 전용 |
| 배치 | `land`, **광맥 풍부도 > 0인 칸만** |
| 비용 | 무겁게 — 목재·석재 대량 + 철 + 도구 (갱목과 버팀대) |
| 슬롯 | 채광꾼 4 (기존 직업 재사용) |
| 산출 | `richnessAt(칸) × 기본채굴률 × 숙련·도구 보정` — 잔량 > 0인 동안 |
| 부산물 | 철맥 채굴 시 돌 소량 동반 (기존 `mineStone` 부산물 비율 재사용) |

- 채광장(노두 채집형)과 달리 **실내 작업장** — 채광꾼이 갱 안에서 일한다
  (`workplacePresentation` interior 패턴, 대장간과 동일)
- 중심에 지을수록 산출이 높다 — 허생의 정보 우위가 우물과 똑같이 작동
- 광맥이 비면 채광갱은 놀고, 로그로 "맥이 다했다"를 알린다. 철거·이전은 기존 규칙대로

## 5. 밸런스 방향

- **capacity는 노두 총량의 수 배** — 채광갱 하나가 수 년을 버티는 규모로 시작.
  지하마저 비는 시점은 사실상 초장기 플레이의 지평선으로 둔다
- 채굴률은 채광장보다 약간 높게 (후반 건물답게) 하되, 건설비가 무거워 노두가 남아
  있는 동안에는 채광장이 여전히 합리적이어야 한다 — 채광갱은 대체가 아니라 계승
- 광맥 수는 지도당 철 2~3 + 석 2~3에서 시작 (수맥 4~6과 나란히, 겹침 허용)

## 6. 구현 순서

| 단계 | 내용 | 의존 |
|---|---|---|
| M1 | 광맥 생성 — 수맥과 공용 헬퍼로 추출 (`veinField` 패턴) + 잔량 상태 + 세이브 +1 | 우물 U1과 동시 작업 권장 |
| M2 | 광물 레이어 렌더 (종류 색 + 허생 농담) + 배치 모드 자동 표시 | M1, 우물 U4와 코드 공유 |
| M3 | 채광갱 건물 + 배치 검증 + 채광꾼 갱내 작업 | M1 |
| M4 | 허생 능력 갱신 (수맥·광맥 관측 통합) | M2 + 우물 U4 |

M1·M2는 우물 문서의 U1·U4와 **같은 작업자가 같은 시기에** 하는 것이 이득이 크다 —
기하·레이어·허생 연동이 전부 공유 코드이기 때문이다.

## 7. 갱도 붕괴 — 재해 문서로 확정

채광갱의 필연적 그림자. 상세는 재해 문서 §3-9 (D9 단계, M3 의존).

이 문서와 얽히는 규칙만 요약하면 —

- 발생 가중치의 **깊이 축이 광맥 잔량**이다: 잔량이 낮을수록 위험.
  말라 가는 광맥의 마지막 한 줌을 쥐어짤지, 안전할 때 새 갱을 팔지가 후반 결정이 된다
- 전조 경고에 대한 대응은 기존 작업 슬롯 해제 — 새 UI 없음

## 8. 열어 둔 판단

- 지하 광맥마저 소진된 뒤 — 교역 의존으로 전환할지, 극소량 재생을 줄지 (초장기 관찰 후)
- 채광갱의 겨울 보너스 — 갱내는 바깥 날씨를 안 타는가 (실내 작업장이므로 자연스럽지만
  채광장과의 격차가 커질 수 있어 관찰 후)
- 석맥 위 채광갱의 석재 산출이 성벽·석성 수요와 맞는 규모인지
